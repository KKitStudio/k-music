## 一键启动入口 + 双击打不开页面修复
- 现象：用户直接双击 `mt-gui.exe` 提示打不开页面。根因：GUI 把前端写死成 CWD 相对 `./app/gui/frontend`，双击时 CWD=exe 目录（`target/release`），找不到前端 → ServeDir 404。
- 修复：
  - `serve::resolve_frontend_dir(exe_dir, cwd)` 级联解析（exe\frontend → exe\app\gui\frontend → exe\..\..\app\gui\frontend → cwd\app\gui\frontend），返回首个含 index.html 的目录。GUI 与 CLI `serve` 共用。
  - 端口绑定失败（旧实例未退出）自动回退随机空闲端口（`server.port` 默认 0）。
  - 开 WebView 前轮询后端端口至可连接（≤5s）。
- 新增干净发布文件夹 `dist/`：`mt-gui.exe`（一键入口）+ `mt-cli.exe` + `frontend/`。双击 `dist/mt-gui.exe` 即启动，无需先开 CLI。
- `tools/package_gui.bat`：Windows 双击即重新编译并汇总到 `dist/`。
- `.gitignore`：忽略 `/target/`、`/dist/`、`musicmt-launcher.toml`、`musicmt-guest.toml`、`musiclibrary/`。
- 验证：从 `dist/` 起 `mt-cli serve`，`GET /`→200(index.html 9257B)、`/api/status`、`/app.js`→200；前端解析日志 `frontend_dir=D:\project\musicMT\dist\frontend` 正确。

## NCM 工具逻辑梳理 + 散落 .ncm 整理（用户 2026-10-28 两项需求）
- 需求：① 扫描发现曲库内 `download/` 之外的 `.ncm` → 列表询问，建议移入 download 按下载 NCM 落点处理；② 梳理 NCM 工具三种时序；新规则「只要指定了工具就自动转换」。
- 核心改造（已编译+测试+端到端实测）：
  - `config::NcmConfig::tool_ready()` 成为唯一开关（工具路径存在且为文件）；默认 `tool_path` 清空（去掉开发机残留路径）；`build_library_config` 仅在 `.mt/tools/` 检测到时写 `tool_path`。旧 `enabled` 字段保留仅作兼容写入，运行期一律以 `tool_ready()` 为准。
  - `library::scan_library`/`scan_dir` 收集 `download/` 体系（ing/ncm/pendingNcm/_ncm_raw）之外、扩展名 `.ncm` 的文件 → `ScanStats.loose_ncm: Vec<String>`（只记录不入库）。
  - `import::import_ncm` 改 `pub`；无工具分支加「已在 pendingNcm 则跳过」守卫（避免重命名到自身）；新增 `import::process_pending_ncm(cfg,conn)->ImportResult` 遍历 `download/pendingNcm/` 转换入库（指定工具后自动清积压）。
  - serve：AppState 增 `last_ncm_found: Arc<Mutex<Vec<String>>>`；`scan_handler` 响应加 `ncm_found` 并写入共享列表；`status` 返回 `tool_ready`/`loose_ncm`/`pending_ncm`；`ncm_tool_handler` 保存后调 `process_pending_ncm` 回传积压结果；新增 `POST /api/ncm/organize {paths}` 逐个 `import_ncm(Move)`。`status_handler` 内不能用 `blocking().await`（破坏 axum `Send`），改用同步 `read_dir`。
  - CLI：`mt-cli scan` 打印散件列表；`verify` NCM 行改 `tool_ready()+待转换/散落计数`；新增 `mt-cli ncm-organize`（先清 pendingNcm 积压、再处理散落文件，避免重复计数）。
  - 前端 `ncm-organize-modal`：扫描完成/status 加载发现散件即弹窗，默认「移入 download 并处理（推荐）」+「暂不处理」；`applyNcmTool` 显示积压转换结果。
- 实测：① 无工具 organize 2 散件 → `pendingNcm` 2、0 失败；② serve 端到端：`POST /api/ncm-tool`（假工具）前 `pending_ncm:2,ncm_enabled:false` → 后 `backlog.imported:2,pending_ncm:0`，曲库新增 2 首（song_id=null）。
- 三种时序（docs/05 §6.1 / docs/07 §3.1 一致）：① 初始化未指定→暂存 pendingNcm；② 初始化即指定→即时转换；③ 之后指定→瞬时 `process_pending_ncm` 自动清积压。结论：指定工具是触发转换的唯一动作，与何时初始化无关。
- 文档：`docs/05 §6` 重写（核心规则+三时序表+§6.2 散落 ncm 处理）；`docs/07` L7 新增散落 ncm 验证、C 组重写（tool_ready + 三时序）、§3.1 对齐 docs/05。
