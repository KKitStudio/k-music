## 设置页外观三项改进（跟随系统 / 主题色对齐 / 原生标题栏同色）

## 修复：导入云音乐曲库后主窗口无响应、点击歌曲无法播放

**现象**：点击「从本地网易云曲库更新」导入后，回到歌曲列表点击歌曲无法播放；用户初步判断是「导入列表抢占了主窗口焦点」。

**排查（排除法）**：
- 播放链路本身无碍：`playTrack` 用 `/api/audio/:local_id` → `db::lookup_path_by_local_id` → 按 `file_path` 手写 Range 流式返回；网易云导入走 `import_folder_with_progress`（Copy），把真实音频拷入曲库并登记有效 `file_path`，与任何普通导入一致。
- 主列表点击/双击绑定完好（`renderTracks` 的 `tr` click→select、dblclick→play）。
- 进度面板 `#progress-panel` 是右下 400px 浮层（`z-index:60`、`pointer-events` 正常），不吞主窗口原生焦点——它只是恰好在对话框后出现，被误判为元凶。

**根因**：真正吃掉焦点的是 `rfd::FileDialog`（Windows 原生模态对话框）。「未设置网易云曲库目录」时 `runImportNetease` 先调 `/api/pick-folder` 弹原生框；框关闭后 WebView 常未自动重获焦点，主窗口表现为「无响应 / 点击不生效」，从而点歌不播。

**修复**（沿用标题栏染色的 `OnceLock<fn()>` 钩子模式）：
- `serve.rs`：新增 `set_post_dialog_focus_sink(fn())` + `restore_focus_after_dialog()`；三个 `rfd` 处理器 `pick_folder` / `pick_library_directory` / `pick_ncm_tool` 在 `rfd` 返回后调用之。
- `mt-gui/src/lib.rs::native_titlebar`：新增 `refocus()`（`#[link(user32)] SetForegroundWindow`+`SetFocus` 把主窗口带回前台并夺回键盘焦点）；`setup` 里 `set_titlebar_color_sink` 旁注册 `set_post_dialog_focus_sink(native_titlebar::refocus)`。`CLI serve` 未注册则空转。
- `SetForegroundWindow` 在对话框关闭的同源时序内调用（用户刚交互过、进程持前台权限），应能可靠夺回焦点。

**验证**：`cargo build --release -p mt-core -p mt-gui` EXIT=0；`cargo test -p mt-core` 46 passed；`tools/package_gui.bat` 跑通、`dist/kqk-app.toml`/`.guest/` 保留。原生窗口行为需真机目视（与标题栏染色同属 Windows 原生相关）。

### 踩坑（重要，易回归）
1. **逐列 Math.round 会累积误差**：6 列各 round 一次，和可能比 avail 多 1~2px → `table-layout:fixed` 下总宽超出 → 浏览器重新分配并**撑宽表格**（出现横向滚动）。必须用累计取整，且 `tableAvailWidth()` 用 `Math.floor(total - fixed)`。
2. **border-box 下 padding 不可压缩**：`.track-table th` 左右 padding 各 12px，列宽窄于 24px 时浏览器会强制撑宽该列 → 表格溢出。故像素下限取 `MIN_COL_PX = 48`（24 padding + 留文字宽度），**不是**纯百分比下限。
3. **配置解析陷阱**：TOML 文档整体 `toml::from_str::<UiConfig>` 会把 `[ui]` 当**未知字段丢掉**（serde 默认忽略未知字段）→ 读回的全是默认值。必须 `doc["ui"].clone().try_into()`。这曾让「写回 artists=1」断言读到默认 2，排查耗时。
4. **追加位置**：缺失键若在文件末尾统一追加，会落到**下一个表头之后**（变成别的段的键）→ 必须在 `[ui]` 段内就地补齐。
5. 前端拖拽后的比例要与后端 `sanitize()` 规则一致（<4% 抬到默认 + 总和归一 100），故前端加 `normalizeStoredWidths()` 与后端同规则，避免内存与文件不一致。

## demo 测试脚手架加固（本轮收尾）
- **`common.start_server()` 改为「失败即回收」**：解析端口阶段若抛错（历史教训：脚本漏 `import re`/`import time`），Popen 出的 `mt-cli.exe serve` 会变成**孤儿进程**，持续占用 exe → 运行目录删不掉。原先 `start_server()` 在用例的 `try` **之外**，泄漏不可避免；现改为 `test_ui_prefs.py` / `test_real_config.py` 把服务启动放进 `try`，并统一用 `common.start_server/stop_server`。
- **新增 `common.kill_stale_servers()`**：按 **ExecutablePath 位于 `demo/.run/` 下** 判定（用 `Get-CimInstance Win32_Process` 取 PID+路径），只杀运行目录里的孤儿 mt-cli，不会误杀用户自己启动的服务。`clean_run.py` 先调它再删目录。
- **`clean_run.py` 不再谎报成功**：原来 `shutil.rmtree(ignore_errors=True)` 在 Windows 上静默失败，却照样打印「已清理」→ 磁盘占用假象。现改为 `onerror` 回调清只读属性重试，失败项**如实报告**「清理失败（文件被占用）」。同时清理 `.run/` 根目录下所有散落文件（DOM dump、`*.new` 等历史手工产物）。
- **修好 `run_old_regression.py`**：原先 `sys.path.insert` 在 `import sys` **之前** → `NameError: name 'sys' is not defined`，脚本从来跑不起来。现已修好并实测：修复前前端跑同一套断言 **C 组失败 26 条**（正是占位文案症状）。
- **`run_preview.py` 的 DOM dump 改写入 `C.run_dir('dom')` 带时间戳子目录**，不再污染 `.run/` 根目录。
