## GUI 启动预检 WebView2 运行时（原 TODO「可选增强」落地）

- 需求：双击 `mt-gui.exe` 后若系统缺 WebView2，友好提示而非白屏/崩溃。
- 实现：`app/gui/src/lib.rs` 新增 `#[cfg(windows)] mod webview2_check`，`run()` 创建 Tauri 窗口前调 `ensure()`。
- 关键决策（踩坑修正）：
  - ❌ 初版用注册表检测（`EdgeUpdate\Clients\{F3017226-...}` GUID + `is_windows11` 按 CurrentBuild>=22000）。**否决**：本机 Win10 Pro（CurrentBuild=26300 但 ProductName=Win10）实测该 GUID 注册表**根本不存在**——现代 WebView2（尤其 Edge 随附版）常不写注册表，此方案会误杀所有 Win10 已装用户；CurrentBuild 判 Win11 也会误判。
  - ✅ 终版用**微软官方 API** `GetAvailableCoreWebView2BrowserVersionString`（webview2-com-sys 暴露），权威覆盖 Win11 内置 / Edge 随附 / 独立安装。
- 依赖：`app/gui/Cargo.toml` 加 `webview2-com-sys = "=0.39.1"` + `windows-core = "=0.62.2"`（均在 Cargo.lock，零新增体积）。
- 链接：webview2-com-sys 在 msvc 下 `#[link(name="WebView2LoaderStatic", kind="static")]` 静态链接——即 dist 无 `WebView2Loader.dll` 的原因，符号必可达（Tauri 同源）。正确引用路径：`webview2_com_sys::Microsoft::Web::WebView2::Win32::GetAvailableCoreWebView2BrowserVersionString`（不在 crate 根）。
- `is_missing() -> bool` 抽出检测逻辑，`ensure()` 调它；成功时 API 返回版本串需 `CoTaskMemFree` 释放。缺失则 `MessageBoxW` 原生弹窗 + `cmd /c start` 打开下载页 + `exit(1)`。
- 验证：`cargo test -p mt-gui` 的 `webview2_check::tests::local_machine_has_webview2` 在本机（已装 WebView2）断言 `is_missing()==false` 通过；release 构建通过并同步 `dist/mt-gui.exe`。**未升版本号**（仍 v0.4.0 元数据），随下次发版正式带出。
