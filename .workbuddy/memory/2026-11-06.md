## GUI 启动预检 WebView2 运行时（原 TODO「可选增强」落地）

- 需求：双击 `mt-gui.exe` 后若系统缺 WebView2，友好提示而非白屏/崩溃。
- 实现：`app/gui/src/lib.rs` 新增 `#[cfg(windows)] mod webview2_check`，`run()` 创建 Tauri 窗口前调 `ensure()`。
- 关键决策（踩坑修正）：
  - ❌ 初版用注册表检测（`EdgeUpdate\Clients\{F3017226-...}` GUID + `is_windows11` 按 CurrentBuild>=22000）。**否决**：本机 Win10 Pro（CurrentBuild=26300 但 ProductName=Win10）实测该 GUID 注册表**根本不存在**——现代 WebView2（尤其 Edge 随附版）常不写注册表，此方案会误杀所有 Win10 已装用户；CurrentBuild 判 Win11 也会误判。
  - ✅ 终版用**微软官方 API** `GetAvailableCoreWebView2BrowserVersionString`（webview2-com-sys 暴露），权威覆盖 Win11 内置 / Edge 随附 / 独立安装。
- 依赖：`app/gui/Cargo.toml` 加 `webview2-com-sys = "=0.39.1"` + `windows-core = "=0.62.2"`（均在 Cargo.lock，零新增体积）。
- 链接：webview2-com-sys 在 msvc 下 `#[link(name="WebView2LoaderStatic", kind="static")]` 静态链接——即 dist 无 `WebView2Loader.dll` 的原因，符号必可达（Tauri 同源）。正确引用路径：`webview2_com_sys::Microsoft::Web::WebView2::Win32::GetAvailableCoreWebView2BrowserVersionString`（不在 crate 根）。
- `is_missing() -> bool` 抽出检测逻辑，`ensure()` 调它；成功时 API 返回版本串需 `CoTaskMemFree` 释放。缺失则 `MessageBoxW` 原生弹窗 + `cmd /c start` 打开下载页 + `exit(1)`。
- 验证：`cargo test -p mt-gui` 的 `webview2_check::tests::local_machine_has_webview2` 在本机（已装 WebView2）断言 `is_missing()==false` 通过；release 构建通过并同步 `dist/mt-gui.exe`。**未升版本号**（仍 v0.4.0 元数据），随下次发版正式带出。

## 两个 bug 修复：启动主题闪烁 + 窗口位置不记忆（10:44–11:12）

**用户报障**：①「设置主题关闭后，再启动还是会闪一下默认主题后才会切换到设置的主题」；②「移动应用窗口后，关闭应用，再打开还是默认位置，应该是上次关闭前的新位置」。

### 根因（比表面更隐蔽）
1. **主题闪烁**：`styles.css` 的 `:root` 是浅色默认值，外观由 body 末尾的 `app.js::applyAppearance()` 应用，且 `/api/status` 是异步的 → 首帧必然是默认浅色。**更关键**：GUI 服务端口动态（`spawn_server` 端口占用时 `bind((ip, 0))` 回退随机端口），而 `localStorage` 按 origin（含端口）隔离，端口一变缓存全失效，于是每次都要等接口回来才能切到 TOML 里的深色。仅补前端缓存治标不治本。
2. **窗口位置**：`WebviewWindowBuilder` 只硬编码 `inner_size(1100,720)` / `min_inner_size(900,600)`，既没有读也没有保存位置 / 尺寸 / 最大化态，Tauri 2 不自动持久化。

### 决策与改动
- **备份**：`.workbuddy/backups/2026-11-06-theme-flash-window-position/`（10 个文件 + MANIFEST.md5）。
- **主题**（`serve.rs` / `index.html`，**app.js 零改动**）：
  - `AppState` 加 `frontend_dir`；新增 `/` 与 `/index.html` 路由 → `index_handler`：读磁盘 `index.html`，把 `appearance_json(&ui)`（权威源 `kqk-app.toml [ui]`）内联注入 `<!--KQK_BOOT_APPEARANCE-->` 占位符，响应 `Cache-Control: no-store`；注入 JSON 经 `escape_for_inline_script()` 转义 `<` `>` `&` 防 `</script>` 提前闭合；**无占位符的旧前端原样返回**（build.rs 未同步也不会坏）。
  - `index.html` 的 head 加首屏内联脚本（CSS link 之前）：`saved=true` 时用注入配置、`saved=false` 时沿用本地旧偏好（保留迁移语义）；设 `data-theme` / `data-theme-mode` / `--primary` / `--primary-dark`（派生系数与 `applyAppearance()` 一致 0.72 / 0.78），并**把权威外观回写 `localStorage`**（保留自定义皮肤 `skin.src`）——否则 body 末尾 `applyAppearance()` 会拿陈旧缓存把首帧主题覆盖回去，仍会闪。预设皮肤 gradient / name 随后由 `syncAppearanceFromStatus()` 用 `SKIN_PRESETS` 补全。
  - 复核时发现的隐藏坑：只做 head 预置不够，`applyAppearance()` 读的是 localStorage；回写缓存是让「不改动 app.js」成立的关键。
- **窗口位置**（新增 `app/gui/src/window_state.rs`，`lib.rs` 接线，**config.rs 零改动**）：
  - 单独存 `<exe目录>/kqk-window.state`（物理像素 `key=value`，临时文件 + rename 原子替换）。**刻意不写 `kqk-app.toml`**：`/api/ui-prefs` 从 axum 线程的内存 `UiConfig` 副本整段 `save_ui_in_place()` 写 `[ui]`，GUI 侧若混写同一文件，任一方拿旧副本落盘都会抹掉对方最新值。
  - `track()` 监听 `Moved` / `Resized` / `CloseRequested` / `Destroyed`；最大化期间跳过几何（避免写入边框负偏移）；用户从未动过窗口且无历史状态时不写盘（保持系统默认居中）。
  - 恢复：`app.available_monitors()` 校验窗口矩形与当前显示器交集 ≥160×120，外接屏拔掉 / 改分辨率时回退默认居中；`visible(false)` → `set_position(Position::Physical)` + `set_size(Size::Physical)` → `show()`。**查证 Tauri 2.12.5 源码**：builder 的 `position/inner_size` 只接受逻辑像素，直接塞物理值会在高 DPI 下偏移，故必须 build 后用 Physical 恢复；`WindowEvent` 用的是 `tauri::app::WindowEvent`（`CloseRequested { api }`，`#[non_exhaustive]`）。
  - `.gitignore` 加 `kqk-window.state` / `kqk-window.state.tmp`。
