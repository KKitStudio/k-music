# 02 系统架构与模块设计

> Phase 1 整体分层架构、模块职责与关键流程。技术选型见 04。
> 核心为 **纯 Rust 库（crate）**，GUI 壳（Tauri + Web 前端）与 CLI 为两个薄消费者。

## 1. 总体架构（分层）

```
┌─────────────────────────────────────────────┐
│  交互层 (Interface)                         │
│  GUI 壳（Tauri + Material Web）：曲库列表 + 底部播放栏  │
│  CLI（scan / sync / import / logout 等，headless 运维）│
└───────────────────┬─────────────────────────┘
                    │ 调用核心库 API（同进程 FFI / 同 crate）
┌───────────────────▼─────────────────────────┐
│  核心逻辑层 (core crate, 纯 Rust, UI 无关)   │
│  认证 · 网易云客户端 · 同步编排 · 下载 ·     │
│  本地曲库+扫描 · 导入 · NCM 转换接口 ·       │
│  音频属性抽取 · 配置 · 播放文件服务          │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  基础设施层                                 │
│  SQLite 存储 · 文件 IO · 日志 · 加密 ·      │
│  （音频解码由 UI 壳/系统承担，核心不捆绑）  │
└─────────────────────────────────────────────┘
```

设计原则：
- **核心逻辑与平台/UI 无关**：所有 Windows 专有行为收敛在基础设施层；核心 crate 不依赖 Tauri/Web/GUI。
- **NCM 转换**为独立可插拔模块，仅通过命令模板与外部工具交互。
- **扫描/导入/播放文件服务**均为独立能力，可单独触发。
- **交互层可替换**：GUI 壳 / CLI / 未来 Flutter 壳，三者都只消费核心 API。

## 2. 模块职责（均在 core crate 内，或壳层薄封装）

### 2.1 认证模块 (Auth) ⛔ 已移除（2026-10-29）
- 原扫码登录 + 登录态加密存储（`aes-gcm`）+ 退出登录释放设备槽位 + 带鉴权请求客户端的整套逻辑**已随服务端功能移除**。
- 未来若恢复下载能力，将基于网易云**官方开发者 API**（OAuth 授权）另起授权模块，与原有非官方 WEAPI 实现无关（见 00 §3 / 01 FR-01）。

### 2.2 网易云客户端模块 (NetEaseClient) ⛔ 已移除 / 预留
- 原封装歌单/喜欢/下载 URL/配额/VIP 端点与签名加密的逻辑**已移除**。代码保留为未来基于官方开发者 API 复用下载窗口的参考。

### 2.3 同步与编排模块 (Orchestrator) ⛔ 服务端同步已移除（2026-10-29）
- 原「拉远端 → 比对 → 生成下载清单 → 配额 → 调度下载 → 自动登出」的服务端同步路径已移除。当前核心仅保留本地能力：扫描、导入（FR-10）、从本地网易云音乐曲库更新（FR-14）、NCM 转换、播放文件服务。

### 2.4 下载模块 (Downloader) ⛔ UI 隐藏 / 代码预留
- 并发下载落盘（`download/ing`→`download/`→`file_scheme` 组织）逻辑**代码保留、UI 隐藏**，以便未来复用下载窗口（可能基于官方开发者 API）。
- 当前版本不经过此模块产生任何下载；`.ncm` 转换产物的落盘仍走 `download/ncm` 归档目录（见 FR-07）。原 `[download]` 配置段（concurrency/retry）已删除，复用时应重新定义。

### 2.5 本地曲库与扫描模块 (Library + Scanner)
- SQLite 读写：songs / playlists / playlist_tracks / download_records / conversion_records / sync_log / quota_state。
- **扫描**：遍历曲库根（含 `download/` 体系，暂存子目录 `ing/ncm/pendingNcm` 跳过）抽取音频属性写入索引；**增量门控**——仅当文件 `(size, mtime)` 与缓存不符才调用 `lofty` 抽取，未变文件直接复用记录（详见 03 §5.1）。
- **外部增删检测（档位②）**：扫描末尾 `prune_missing` 清理磁盘已不存在的记录（孤儿清理）；app 启动自动跑一次扫描 + 点"扫描"手动触发（详见 03 §5.2）。
- 本地扫描/导入文件 `song_id=NULL`、不建 `songs` 行；播放/详情/封面按 `local_id` 检索（id 空间与网易云解耦）。
- 提供「是否已存在且音质足够」「可升级」等查询。

### 2.6 导入模块 (Importer)
- 接收外部源文件夹 + 方式（copy/move）。
- copy：保留源；move：写入校验成功后删源（破坏性，须先确认 + 先写后删，失败即中止保留源）。
- 按 `config.library.file_scheme` 组织归位（默认 `<artist>/<album>/<title>.<ext>`）；复用扫描逻辑做属性抽取与 DB 登记；song_id 走"存量回溯"模糊匹配。

### 2.7 NCM 转换接口模块 (NcmConverter)
- 读配置工具路径与命令模板；检测存在性（`tool_ready()`）；对 `.ncm` 调用（工具就绪即自动转换）。
- **原 NCM 单独存放、不删除**：有工具转换后，原始 `.ncm` 归档于 `download/ncm/`；无工具时暂存 `download/pendingNcm/`（旧顶层 `_ncm_raw/` 已废弃，统一到 `download/` 体系，见 docs/05 §11）；解密产物按 `file_scheme` 置于曲库正式位置。
- 探测产物格式并抽取音质属性登记。
- **静默执行（2026-11-04）**：调用外部工具统一经 `mt_core::silent_command()` 创建子进程（Windows 下置 `CREATE_NO_WINDOW = 0x08000000`），**不分配也不显示控制台窗口**，避免 GUI 场景下每转换一首歌就闪一次终端窗口、抢焦点。
  - 根因：GUI 父进程（PE GUI 子系统）创建 Console 子进程（ncmdump.exe，PE Subsystem=3）时，Windows 会自动分配并显示控制台窗口。
  - 上游工具无静默开关：ncmdump（taurusxin/ncmdump）仅有 `-h/-v/-d/-r/-o/-m`，`[Done]` 输出为无条件 `std::cout`，故只能在**调用侧**解决。
  - 附带收益：改用 `Command::output()` 捕获 stdout/stderr，工具失败时可把工具自身错误信息带入错误消息。
  - 验证判据：子进程内 `GetConsoleWindow()` 返回 NULL 即无控制台窗口。

### 2.8 音频属性抽取 (Infra)
- 基于 `lofty`（Rust，覆盖 mp3/flac/m4a/wav/ogg 等）抽取 sample_rate/bit_depth/bitrate/channels/duration/format。
- 可选 `ffprobe` 作冷门格式回退。
- 输出统一质量结构，供升级判定。

### 2.9 播放文件服务模块 (PlaybackServer)
- 在 localhost 起轻量 HTTP 服务（axum），**手写 Range/206 流式响应**（tower-http `ServeFile` 在 axum 0.7 下未实现 `IntoResponse`，故自实现），按 `local_id` 检索 `download_records` 取路径流式返回音频（`<audio>` 拖动 seek 必需）。
- 封面按 `local_id` 取内嵌 APIC，无则 204；仅暴露 musiclibrary 内文件，绑定 127.0.0.1；供 GUI 壳 `<audio src>` 使用。
- 这是核心"提供文件 URL"的接口，也是 UI 壳可替换的支点（Flutter 壳同样消费）。

### 2.10 配置模块 (Config)
- 读取/校验**两份配置**：app 级 `<exe 目录>/kqk-app.toml`（应用设置 + 当前曲库路径）与曲库级 `<曲库根>/.mt/config.toml`（曲库名称 / 结构方案 / 目录布局）；运行期由 `config::Config::merge` 合并为单一视图。
- GUI 通过 `/api/status` 返回当前 `library_dir`、`library_configured`、`file_scheme`、`ncm_ready`、`netease_library_dir` 等状态。首次指定曲库时 `library_directory_handler`（`POST /api/library-directory`）执行**完整初始化**：canonicalize 目录、建 `.mt/`、写 config.toml（含 `download_root`/`ncm_raw_dir=download/ncm`/`library.file_scheme`）、建 library.db 与 README、建 `download/{ing,ncm,pendingNcm}`、NCM 检测、写 app 配置 `kqk-app.toml` 的 `last_library_dir`，随后**换库**（替换 `AppState` 的 cfg/conn 并触发后台扫描）。主界面「设置」可改曲库位置、切换 `file_scheme`（触发全量重组，见 docs/05 §4c）、配置 NCM（见 docs/05 §6）。
- `/api/pick-library-directory` 打开系统原生目录选择窗口并返回所选路径；取消选择时不更改输入内容。

### 2.11 歌词模块 (Lyrics)
- **来源优先级**：同名 `.lrc` 边车文件（Sidecar）→ 音频内嵌歌词（Embedded）。
- 边车查找：优先精确同名 `<stem>.lrc`，其次曲库目录内大小写不敏感扫描。
- 文本解码：UTF-8 BOM / UTF-16 BOM / UTF-8 / **GB18030**（`encoding_rs`，应对国内常见 GBK 歌词文件）。
- 内嵌提取：ID3v2 `USLT`（**自研解析**：synchsafe 尺寸、扩展头、反同步、逐帧扫描、内容描述符分隔；编码字节 0=Latin1 / 1=UTF-16 BOM / 2=UTF-16BE / 3=UTF-8）+ Vorbis `LYRICS` 注释（FLAC / OGG）。原因：lofty 通用 `Tag` 转换会丢弃 ID3v2 `USLT`，且 `ItemKey` 无 Lyrics 变体。
- **导入联动**：`import_audio_file` 在移动源音频前捕获边车文件，归位后同步落一份同名 `.lrc`；`import_ncm` 暂存 `.ncm` 时一并搬运 `.lrc`。自定义文件夹导入与「从本地网易云音乐曲库更新」两条路径均汇聚此函数，一处改动覆盖全部。
- 对外接口：`GET /api/lyrics/:id` → `{ok, source("lrc"|"embedded"), timed, text}`。

### 2.12 应用元信息模块 (App)
- `app/core/src/app.rs` 为应用名称/版本/作者等元信息的**唯一数据源**；版本号取 `env!("CARGO_PKG_VERSION")`，改根 `Cargo.toml` 一处即全局同步。
- 窗口标题、顶栏品牌名、`document.title`、设置「关于」面板、CLI `--version` 五处显示**同源**。
- 对外接口：`GET /api/about`（name / legacy_name / version / author / email / license / description / tech）；`/api/status` 另返回 `app_version`。

### 2.13 GUI 壳 / 播放栏（壳层，非核心）
- Tauri 窗口内嵌 Material Web 前端 SPA。
- **曲库列表**：调核心查询渲染 曲名/艺人/专辑/音质/时长。
- **底部播放栏**：`<audio>` 元素 + 播放/暂停 + 可拖动进度条 + 时间显示；双击列表项 → `audio.play()`；拖动 → `audio.currentTime`；`timeupdate` → 回显。
- **歌词浮层**：播放栏「词」按钮开关 `#lyrics-drawer`；`playTrack()` 时调 `/api/lyrics/:id` 拉取歌词，`parseLrc()` 解析时间轴（`[mm:ss]`/`[mm:ss.xx]`/`[mm:ss.xxx]`、一行多时间戳、元信息行不入轴），`timeupdate` → `syncLyrics()` 高亮当前行并居中滚动；纯文本（无时间轴）整段展示。
- **导入/同步/扫描**等操作用核心 API 触发并展示结果。
- **网易云服务端入口已全部移除（无门控开关）**：2026-10-29 起主界面**不再渲染**任何网易云服务端入口——无顶栏「配置网易云音乐」、无工具栏「下载/更新云音乐曲库」「下载管理」、无设置「网易云音乐」区块（见 01 FR-12）。原 `netease.login_enabled` / `netease.configured` 等门控字段已删除。
- **始终显示**：①「从本地网易云音乐曲库更新」按钮（本地增量导入，见 FR-14）；② NCM 设置区块（见 FR-07）。两者均与任何开关无关。
- 未来若恢复下载（基于官方开发者 API），将作为新模块重新引入对应 UI 入口，而非复用已删除的 WEAPI 门控。
- **外观主题三态与原生标题栏同步（2026-11-05）**：设置→「外观」的主题模式为 `light / system / dark`，`system` 为默认，由 `matchMedia('(prefers-color-scheme: dark)')` 解析；`data-theme` 存**解析后**明暗，`data-theme-mode` 存设置值。前端 `applyAppearance()` 每次把当前强调色 POST `api/appearance/titlebar`；`mt-core::serve` 用 `OnceLock<fn(u32, bool)>` 回调把 COLORREF 转交 GUI 壳，`mt-gui::native_titlebar` 调 `DwmSetWindowAttribute` 设 `DWMWA_CAPTION_COLOR`(35) / `DWMWA_TEXT_COLOR`(36)，Win10 退化用 `DWMWA_USE_IMMERSIVE_DARK_MODE`(20)。CLI `serve` 模式未注册回调 → 接口静默空转；窗口创建前收到的颜色会在 `bind()` 时补刷。
- **布局风格与列表列宽（2026-11-05）**：
  - **布局风格**：四个页面（全部曲库 / 播放列表 / 专辑 / 歌手）**各自独立**设置「横向 / 纵向」。
    横向(1) = 曲目详情在窗口右侧独立详情栏；纵向(2) = 详情内联到歌曲列表上方（把 300px 让给列表，长曲名/艺人/专辑不被截断）。
    默认：主界面横向，其余三者纵向。前端 `switchTab()` 按当前页面的风格决定显示右侧详情栏还是内联详情条。
  - **列宽比例**：拖动歌曲列表**表头**的列分隔线调整列宽（该列变宽、右邻列等量变窄，总宽不变），
    以**百分比占比**存储（6 个业务列之和恒为 100），写入 `kqk-app.toml` 的 `[ui]` 段；
    窗口缩放 / 布局切换后按占比重新分配像素宽。
  - **接口**：`GET/POST /api/ui-prefs`（部分更新；返回 `layout_styles` + `column_widths`）；`/api/status` 同步暴露这两个字段。
    落盘走 `config::save_ui_in_place()`，只就地替换 `[ui]` 段内的已知键（注释/未知键/键序原样保留）。

### 2.14 导入进度上报模块 (Progress)
- `app/core/src/progress.rs`：`ProgressTracker`（`Arc<Mutex<ImportProgress>>`，可克隆共享同一份状态）+ `ProgressEntry` 动作日志。
- **动作枚举** `ImportAction`：`Copy` / `Move` / `Convert` / `Stage` / `Skip`；**状态枚举** `EntryStatus`：`Imported` / `Skipped` / `Pending` / `Failed`。
- **计数口径刻意分离**：进度条 `processed/total` 与结果计数（imported/skipped/pending/failed）按**源文件**计；动作日志 `recent` 按**真实动作**计。1 个 ncm 源文件会产生「转换」+「入库」两条日志，但只结算为 1 个源文件——避免"进度条走了两格却只入了一首"的误读。
- **增量游标**：`ProgressEntry.seq` 单调递增。因日志列表「新的在前」且有长度上限，按下标取增量会漏/重，故统一用 `entries_after(after_seq)` 按 seq 消费；CLI 与 GUI 共用此语义。
- 接入点：`import_folder_with_progress` / `import_netease_library_with_progress` / `import_ncm_with_progress` / `process_pending_ncm_with_progress`；无进度版本作为向后兼容包装保留。
- 对外接口：`GET /api/import-progress` → `{running, source, total, processed, current_file, current_action, imported, skipped, pending, failed, recent[], latest_seq, last_error}`。
- 失败信息链路：NCM 工具失败时把 stderr 写入 `last_error` 与日志条目，前端进度面板直接展示。

## 3. 关键流程

### 3.1 扫描建库（scan）
```
scan 命令（或 app 启动/点"扫描"触发）
 → 遍历曲库根（含解密产物；ncm 原文件及 download/{ing,ncm,pendingNcm} 暂存子目录不解析）
 → 每文件：查 download_records 缓存 (size, mtime)
     · 一致 → 跳过 lofty 抽取，复用记录（增量门控，03 §5.1）
     · 不一致 → 抽取音质属性，写入/更新 download_records（song_id=NULL）
 → 新增文件入库；变更文件覆盖元数据
 → 末尾 prune_missing：清理磁盘已不存在的记录（外部删除/移动检测，03 §5.2）
 → 输出扫描统计（scanned/inserted/updated/removed）
```

### 3.2 增量同步下载（含音质升级） ⛔ 已移除（2026-10-29，服务端路径）
> 原 `sync` 命令的「加载登录态 → 拉歌单 → 比对 → 配额 → 并发下载 → 自动登出」流程已随登录功能移除。以下仅作历史参考；未来若基于官方开发者 API 恢复，将重写此流程。
```
（已移除）sync 命令
 → 加载配置/登录态（必要时扫码）
 → 拉取歌单 + 喜欢
 → 每 song_id：不存在→下载队列；音质≥desired_tier→跳过；可升级且符合策略→升级队列
 → 应用月度配额 → 并发下载 → 落盘 → 更新索引
 → 失败分类记录 → 新增 .ncm 触发 NCM 转换 → 汇总 → 自动退出登录释放设备
```

### 3.3 NCM 转换
```
发现 .ncm
 → 检查工具配置且存在？否→.ncm 移入 download/pendingNcm/ 暂存、不入库、记 Pending 跳过；是→按命令模板调用
 → 解密产物（原始格式）按 file_scheme 置于曲库正式位置
 → 抽取产物音质 → 经 db::insert_record 登记到 download_records（⚠️ conversion_records 当前未写入，见 docs/03 §2.5）
 → 原 ncm 归档于 download/ncm/，不删除
```

### 3.4 导入（copy / move）
```
import <源文件夹> [--mode copy|move]
 → 列举源内音频
 → 每文件：抽取属性 → 按 file_scheme 组织归位（默认 <artist>/<album>/<title>，缺失标签回退文件名）
 → copy：直接落盘；move：落盘校验成功后删源（失败即中止保留源）
 → DB 登记（song_id 走存量回溯模糊匹配，低置信标 needs_review）
 → 输出导入统计
```

### 3.5 播放
```
GUI 主界面加载曲库列表（核心查询）
 → 双击歌曲 → 核心按 local_id 返回该曲目的本地播放 URL（localhost 服务，见 docs/03 §2.4）
 → <audio src=URL> 播放；底部栏显示进度
 → 拖动进度条 → audio.currentTime（依赖服务 Range/206）
 → 暂停/继续：audio.pause()/play()
```

### 3.6 幂等与续跑
- 以 `song_id` + 音质层级去重；已存在且文件完整则跳过。
- 中断重跑：从本地曲库恢复状态，仅补缺失/升级。
- 月度计数基于持久化 + 服务端本月记录，不受重启影响。

## 4. 数据流向

```
远端(网易云) → 客户端 → 编排层(比对/升级/配额) → 下载 → 文件系统 + 本地曲库(索引)
文件系统(音频) → 扫描 → 音频属性抽取 → 本地曲库(索引, 含音质)
文件系统(.ncm) → NCM 转换 → 外部工具 → 解密产物 → 音频属性抽取 → 本地曲库(转换+音质)
本地曲库(索引) → 播放文件服务(Range) → GUI <audio>（播放）
```

## 5. 与后续阶段的接口预留

- **跨平台**：核心 crate UI 无关，飞牛(NAS)/安卓只需换/加 UI 壳 + 编译目标；GUI 壳可换 Flutter（同样消费核心 API 与播放文件服务）。
- **Web/远程访问**：播放文件服务与核心 API 均为本地 HTTP 友好；未来 NAS 上可暴露为远程访问（加鉴权）复用同一 SPA。
- **多音源**：客户端模块抽象为 `MusicSource` 接口，网易云为首实现。
- **ID3 / 精细命名 / 虚拟专辑视图**：Phase 2 增强，不阻塞 Phase 1。
