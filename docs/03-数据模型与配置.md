# 03 数据模型与配置

> Phase 1 的本地存储（SQLite 表结构）、配置项（TOML）、NCM 外部工具接口规范、存储组织与扫描/导入/播放范围。

## 1. 存储选型

- **SQLite 单文件**（位于 `<曲库根>/.mt/library.db`，数据随曲库走，见 §1.1），零运维、易备份、易随 NAS/手机迁移。
- 元数据库与音频文件分离：音频存文件系统（用户指定的曲库根），索引与音质信息存 SQLite。

### 1.1 项目目录结构（Q3 已定，数据收归 `.mt`）

> 顶层 `app/tools/release` 为项目源码与构建目录；**曲库为用户指定的任意目录**（例：`musiclibrary`），应用数据收敛于其下的隐藏目录 `.mt/`。详见 docs/05。

```
musicMT/                                # 项目源码与构建（顶层固定）
├─ app/            # 源码(core lib + cli + tauri 壳)
├─ tools/          # 开发工具 与 NCM 转换工具源(如 tools/ncm/，构建发布须排除 bin)
├─ release/        # 构建产物
└─ <曲库根>/       # 用户指定的曲库（例：musiclibrary），数据随曲库走
   ├─ download/                   # 已下载完成文件（下载模块落点）
   │  ├─ ing/                     #   下载中临时文件，完成即从 ing 移入 download
   │  ├─ ncm/                     #   已转换 ncm 的原始 .ncm 归档
   │  └─ pendingNcm/              #   无 ncm 工具时，待转换 .ncm 暂存
   ├─ <artist>/<album>/...        # 音乐文件（按 file_scheme 组织，默认 artist_album）
   └─ .mt/                        # 本应用隐藏数据目录（指定曲库时新建）
      ├─ config.toml              #   该曲库配置
      ├─ library.db               #   该曲库 SQLite 索引
      ├─ （auth.json 已移除）      #   网易云登录功能 2026-10-29 删除，本目录不再存凭证
      ├─ app.log                  #   运行日志
      └─ tools/                   #   NCM 解密工具(ncmdump.exe) 存放处
```
> 物理布局只为方便人浏览；专辑/流派/年份等元数据**全部存 DB**，按专辑浏览是 DB 查询而非目录结构。文件组织方案由 `config.library.file_scheme` 决定（默认 `artist_album`：`<artist>/<album>/<title>.<ext>`；另支持 `album`/`artist`/`flat`，见 docs/05 §4a）。NCM 原文件统一在 `download/ncm` 与 `download/pendingNcm`，旧的顶层 `_ncm_raw/` 已废弃（见 docs/05 §2/§11）。

### 1.2 发布 / 打包排除项（合规）
- 对外分享 / 构建 release 时，**必须显式排除 `tools/ncm/bin/`**（ncmdump.exe、libncmdump.dll 及原始 zip）。仅限本地个人使用，不随 app 分发（见 04 §5）。
- 构建脚本的 include/exclude 列表须将 `tools/ncm/bin` 列入排除；或发布说明要求用户自行放置工具并配置 `ncm.tool_path`。

## 2. 数据表设计

### 2.1 songs（曲目主表）
```sql
CREATE TABLE songs (
    song_id       INTEGER PRIMARY KEY,   -- 网易云 song id（稳定唯一；存量/导入无 id 者可为 NULL）
    name          TEXT NOT NULL,
    artist        TEXT,                  -- 艺人（逗号分隔或 JSON）
    album         TEXT,
    duration_ms   INTEGER,
    raw_json      TEXT,                  -- 原始元信息，便于回溯
    needs_review  INTEGER DEFAULT 0,     -- 1=模糊匹配低置信，待人工确认
    created_at    TEXT DEFAULT CURRENT_TIMESTAMP
);
```

### 2.2 playlists（歌单/喜欢集合）
```sql
CREATE TABLE playlists (
    playlist_id   INTEGER PRIMARY KEY,   -- 歌单 id；喜欢列表用固定标识如 -1
    name          TEXT,
    kind          TEXT NOT NULL,         -- 'playlist' | 'liked'
    track_count   INTEGER,
    last_sync_at  TEXT,
    created_at    TEXT DEFAULT CURRENT_TIMESTAMP
);
```

### 2.3 playlist_tracks（集合—曲目关系）
```sql
CREATE TABLE playlist_tracks (
    playlist_id   INTEGER NOT NULL,
    song_id       INTEGER NOT NULL,
    added_at      TEXT,
    PRIMARY KEY (playlist_id, song_id),
    FOREIGN KEY (song_id) REFERENCES songs(song_id)
);
```

### 2.4 download_records（下载记录 / 本地曲库实物 + 音质）
```sql
CREATE TABLE download_records (
    local_id      INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键，恒有值；播放/详情/封面一律按此检索
    song_id       INTEGER,               -- 可空：仅网易云下载有值；本地扫描/导入为 NULL
    source_kind   TEXT NOT NULL,         -- 'download' | 'local_scan' | 'import'
    status        TEXT NOT NULL,         -- 'downloaded' | 'failed' | 'skipped' | 'upgraded'
    file_path     TEXT,                  -- 本地文件路径
    name          TEXT,                  -- 冗余：曲名（本地文件无 songs 行，供列表/详情直取）
    artist        TEXT,                  -- 冗余：艺人
    album         TEXT,                  -- 冗余：专辑
    duration_ms   INTEGER,               -- 冗余：时长
    format        TEXT,                  -- flac | mp3 | m4a | wav | ...
    sample_rate   INTEGER,               -- 采样率 Hz
    bit_depth     INTEGER,               -- 位深（无损 16/24；有损 NULL）
    bitrate       INTEGER,               -- 码率 bps（有损；无损 NULL）
    channels      INTEGER,
    quality_tier  TEXT,                  -- standard|higher|exhigh|lossless|hires
    file_size     INTEGER,
    file_mtime    INTEGER,               -- 增量门控：文件修改时间（秒），用于跳过未变文件的 lofty 抽取
    fail_reason   TEXT,                  -- VIP_ONLY | REGION | URL_EXPIRED | NETWORK | QUOTA
    downloaded_at TEXT,
    FOREIGN KEY (song_id) REFERENCES songs(song_id)
);
```
> 主键已由旧设计的 `id` 改为 `local_id`：本地扫描/导入文件 `song_id=NULL`、不建 `songs` 行，播放/详情/封面一律按 `local_id` 检索（id 空间与网易云解耦）。`name/artist/album/duration_ms` 为冗余存储，`list_tracks`/`get_track_by_local_id` 直接读此表而非 JOIN `songs`。
> 索引「是否已存在且完整」= 该表存在 `status='downloaded'` 且 `file_path` 文件真实存在。
> 音质比较：以 `quality_tier` + `sample_rate` 判断「足够」或「可升级」。
> `file_mtime` 列对旧库通过 `ALTER TABLE ... ADD COLUMN` 迁移补列（docs/03 §5.1）。

### 2.5 conversion_records（NCM 转换记录）
```sql
CREATE TABLE conversion_records (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    song_id       INTEGER,
    ncm_path      TEXT NOT NULL,         -- 原始 ncm 路径（保留，不删除）
    output_path   TEXT,                  -- 解密产物路径（主区）
    tool          TEXT,
    output_format TEXT,                  -- 探测到的产物格式（原始音频格式）
    status        TEXT NOT NULL,         -- 'converted' | 'failed' | 'no_tool'
    converted_at  TEXT,
    FOREIGN KEY (song_id) REFERENCES songs(song_id)
);
```
> ⚠️ 实现状态：该表在 `init_schema` 中已建，但当前代码（NCM 转换走 `download_records` 登记）**尚未写入** `conversion_records`。属于文档早于实现的预留表，待后续确认是否启用或移除。

### 2.6 sync_log（运行记录）
```sql
CREATE TABLE sync_log (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    run_at        TEXT,
    run_type      TEXT,                  -- 'scan' | 'sync' | 'import'
    period_key    TEXT,                  -- 统计周期键，如 2026-10
    downloaded_cnt INTEGER,
    upgraded_cnt  INTEGER,
    summary_json  TEXT
);
```

### 2.7 quota_state（动态配额快照）
```sql
CREATE TABLE quota_state (
    period_key    TEXT PRIMARY KEY,      -- 如 2026-10
    limit_num     INTEGER,               -- 服务端/配置上限（动态获取可为 NULL）
    remaining     INTEGER,               -- 剩余可下载（动态获取可为 NULL）
    fetched_at    TEXT
);
```
> ⚠️ 实现状态：该表在 `init_schema` 中已建，但当前代码动态配额**尚未读写** `quota_state`（仅靠 `vip_download_count` 实时获取，服务端拒绝为最终权威）。属于文档早于实现的预留表，待真机实测配额接口时再决定是否启用缓存。
> 动态模式下「已下载真值」以服务端「会员本月下载记录」统计为准；服务端拒绝(QUOTA)为最终权威。

## 3. 配置项（双配置文件：app 级 + 曲库级）

> **2026-11-04 拆分**：配置不再混在一份文件里，而是按「属于谁」分成两类——
> - **app 级** → `<exe 目录>/kqk-app.toml`：**应用自身**的设置，**外加当前曲库路径**（唯一特例）。
> - **曲库级** → `<曲库根>/.mt/config.toml`：只放**与该曲库相关**的设置（名称 / 文件结构方案 / 目录布局）。
>
> 运行期由 `config::Config` 合并两份（`Config::merge` / `Config::split`），业务代码无感知；
> 持久化时按段拆分：app 级 → `Config::save_app()`，曲库级 → `Config::save_library()`。

### 3.1 app 级配置（`<exe 目录>/kqk-app.toml`）

```toml
last_library_dir = "<曲库根绝对路径>"   # 当前曲库路径（app 级特例：应用必须先知道当前曲库才能找到其配置）

[meta]                          # 版本元信息（两份配置都有，见 §3.4）
config_version = "0.3.0"        # 生成该配置时的构建版本号
min_compatible_version = "0.2.0" # 可正常解析该配置的最低应用版本号

[netease]
# 仅保留本地网易云音乐曲库（导入源）目录；服务端登录/下载相关字段
# （login_enabled / login_method / auth_store / configured / auto_logout_after_sync）
# 已于 2026-10-29 随功能移除，不再存在。
library_dir = ""                   # 本地网易云音乐曲库目录（由官方 APP 维护）；「从本地网易云音乐曲库更新」的默认源，空=未设置。注意：此目录与曲库根是【不同目录】，切勿混淆（见 01 FR-15）。

[ncm]
# 唯一开关 = tool_ready()（tool_path 指向存在的文件）；指定了工具即自动转换所有 .ncm，无需额外开关。
tool_path = "<任意路径>/ncmdump.exe"  # 用户指定的第三方转换工具（可配置）；置空/指向不存在文件 = 未配置
command_template = '{tool} "{input}"'  # 调用模板

[scanner]
audio_meta = "lofty"              # lofty(默认) | ffprobe（冷门格式回退）
match_strategy = "clean_name_db"  # 注意键名：match_strategy（非 match）；干净文件名 + SQLite 索引（DB 为 song_id 真相源）

[import]
default_mode = "copy"             # copy（默认安全）| move（剪切，破坏性须确认+先写后删）

[server]                          # 本地播放用微型 HTTP 服务
host = "127.0.0.1"
port = 0                          # 0 = 随机端口

[logging]
level = "info"                    # 日志**路径**不再持久化：由曲库位置推导（`<曲库根>/.mt/app.log`），避免换库后写错位置

[ui]
track_columns = ["name", "artist", "album", "quality_tier", "duration_ms", "file_size"]  # 歌曲列表显示列（界面偏好，属 app 级）

# ---- 布局风格：每个页面独立 ----
# 1 = 横向（原布局）：曲目详情在窗口右侧的独立详情栏
# 2 = 纵向（新布局）：详情内联到歌曲列表上方，把 300px 宽度让给列表
layout_library = 1                   # 全部曲库（默认横向）
layout_playlists = 2                 # 播放列表（默认纵向）
layout_albums = 2                    # 专辑（默认纵向）
layout_artists = 2                   # 歌手（默认纵向）

# ---- 歌曲列表列宽比例（%）----
# 六个业务列的宽度占比，**之和恒为 100**；单列下限 4%。
# 拖动表头列分隔线即可调整，落盘的是占比而非像素值（窗口缩放后仍按占比自适应）。
width_name = 30.0                     # 曲名
width_artist = 20.0                   # 艺人
width_album = 22.0                    # 专辑
width_quality_tier = 8.0              # 音质
width_duration_ms = 8.0               # 时长
width_file_size = 12.0                # 文件大小
```

> **写回策略**：`[ui]` 段由 `config::save_ui_in_place()` **就地更新** —— 只替换段内的已知键，
> 段内注释、未知键、既有键序全部原样保留（与 `[meta]` 同一策略）；缺失的键追加到段尾。
> 运行期 `Config::merge()` 会调用 `UiConfig::sanitize()` 归一化（布局风格限定 1/2；
> 列宽单列 ≥ `MIN_COLUMN_WIDTH_PCT = 4.0`、总和归一到 100），保证前端拿到的值始终可用。

### 3.2 曲库级配置（`<曲库根>/.mt/config.toml`）

```toml
[paths]
app_data = "<曲库根>/.mt"          # 应用数据根 = .mt（配置/数据库/日志/工具）
download_root = "<曲库根>"         # 曲库根（扫描根）
download_dir = "<曲库根>/download"            # 已下载完成文件落点
download_ing_dir = "<曲库根>/download/ing"    # 下载中临时文件
ncm_raw_dir = "<曲库根>/download/ncm"  # 已转换 ncm 原始归档（顶层 _ncm_raw 已废弃，统一到 download 体系）
tools_dir = "<曲库根>/.mt/tools"   # NCM 转换工具存放处

[library]
file_scheme = "artist_album"       # 曲库文件结构方案：artist_album | album | artist | flat（见 docs/05 §4a）
name = "我的曲库"                  # 曲库名称（多曲库 / 多用户场景下区分；空白回退到曲库目录名，限长 120）

[meta]
config_version = "0.3.0"        # 生成该配置时的构建版本号
min_compatible_version = "0.2.0" # 可正常解析该配置的最低应用版本号
```

### 3.3 旧配置迁移（自动）

升级后首次启动自动完成迁移（`config::load_startup`）：

1. 旧 `musicmt-launcher.toml` 的 `last_library_dir` → app 配置的 `last_library_dir`；
2. 旧曲库 `config.toml` 里混放的 app 级段落（`[netease]`/`[ncm]`/`[scanner]`/`[import]`/`[server]`/`[logging]`/`[ui]`）→ app 配置；
3. 旧曲库配置**内容保留**（不再整份重写），仅按需补写 `[meta]` 版本段。

`[logging] path` 旧键被忽略（路径改为推导）。旧 launcher 文件保留亦无害（仅在 app 配置缺 `last_library_dir` 时作为兜底读取）。

### 3.4 配置文件版本兼容与保留策略（2026-11-04）

**目标**：既有配置文件**不得**在每次构建/启动时被删除或覆盖；只要新旧版本之间不存在逻辑冲突，
就必须**保留现有配置文件及其内容**（含注释、手工添加的未知字段、键序）。

**版本字段**（两份配置都有 `[meta]` 段）：

| 字段 | 含义 |
|---|---|
| `config_version` | **生成时的版本号**（当前构建版本；写入时取 `APP_VERSION`） |
| `min_compatible_version` | **可正常运行的最低版本号**（当前为 `MIN_COMPATIBLE_VERSION` = 0.2.0） |

**兼容判定**（`config::assess_compat`）：

| 情况 | 判定 | 处置 |
|---|---|---|
| 无 `[meta]` 段（旧配置） | `Legacy` | **内容原样保留**，仅就地补写 `[meta]` |
| `config_version` ≤ 当前版本 且 `min_compatible_version` ≤ 当前版本 | `Compatible` | **内容原样保留**；版本信息已是最新时**完全不触碰文件**（连时间戳都不动） |
| `min_compatible_version` > 当前版本 | `Conflict` | 当前程序过旧 → 备份后重建，说明原因 |
| `config_version` > 当前版本 | `Conflict` | 配置由更高版本生成，结构可能已变 → 备份后重建，说明原因 |
| TOML 解析失败 | `Conflict` | 结构/字段不兼容 → 备份后重建，说明原因 |

**冲突处置**：
1. 原文件备份为 `*.conflict-<当前版本>.bak`（用户内容**不丢**）；
2. 重建配置，并**抢救路径类稳定字段**（`last_library_dir` / `netease.library_dir` / `ncm.tool_path`），
   避免用户「重新指定曲库」；语义可能变化的复杂结构（如 `[ui]`）不抢救，回默认；
3. **明确说明冲突原因**（stderr 日志 + 前端「设置 → 配置文件」分区 + `/api/status` 的
   `config_conflict_reason` 字段）。

**保留式写回**（`config::inject_meta` / `upsert_top_level`）：只改写 `[meta]` 段或单个顶层键，
其余内容**逐行原样保留**（注释、未知字段、键序均不丢）。

**构建/打包侧保证**：`app/gui/build.rs` 只同步 `dist/frontend/`；`tools/package_gui.bat` 只拷贝
两份 exe 与 README——**`dist/` 下的运行时产物（`kqk-app.toml` / `.guest/` / `library.db` / `app.log`）
一律不删除、不覆盖**，因此在 `dist/` 内反复构建、反复测试无需重新指定曲库。

**接口字段**（`GET /api/status`）：`config_version`、`config_min_compatible_version`、`config_compat`、
`config_conflict_reason`、`library_config_version`、`library_config_min_compatible_version`、
`library_config_compat`、`library_config_conflict_reason`、`app_version`、`min_compatible_version`。

`paths.download_root` 是本地曲库根目录。GUI 通过「设置曲库目录」输入路径或点击「浏览…」使用系统原生目录选择窗口；首次指定时完成 §5 的初始化（建 `.mt`、写 config/db/README、建 `download/` 体系、NCM 检测、写 app 配置的 `last_library_dir`）。`config.library.file_scheme` 决定文件组织方案；扫描、导入、从本地网易云音乐曲库更新均按此组织。保存目录后应用会立即扫描新曲库，并按磁盘状态更新数据库索引。路径为绝对路径（相对 CWD 已废弃，数据随曲库走）。详见 docs/05。**所有本地路径输入（曲库目录 / NCM 工具路径 / 本地网易云音乐曲库目录 / 导入源文件夹）均须同时提供文本框与「浏览…」按钮，不允许仅手输（见 01 NFR-02 / FR-15）。**

## 4. NCM 外部转换工具接口规范

因版权原因，系统**不实现**解密/转码，仅调用用户自有工具。约定：

1. **工具路径可配置**：`ncm.tool_path` 指向可执行文件（exe/sh/script），建议置于 `tools/`。
2. **存在性检测**：启动时检测路径是否存在；不存在则 `tool_ready()` 为 false（NCM 未配置），下载/导入/散落的 .ncm 暂存 `download/pendingNcm` 不转换。
3. **命令模板机制**：`command_template` 占位符：`{tool}`（工具路径）、`{input}`（待转换 .ncm 路径）、（可选）`{output}`。
4. **调用方式**：拼接后子进程执行（跨平台）；工作目录设为输入文件所在目录。
   - **静默执行（2026-11-04）**：Windows 下子进程经 `mt_core::silent_command()` 创建，置 `CREATE_NO_WINDOW = 0x08000000`，**不显示控制台窗口**（避免 GUI 场景每首歌闪一次终端窗口、抢焦点）。该标志只影响窗口显示，不影响工具行为与退出码。
   - **stdout/stderr 捕获**：改用 `Command::output()`，既避免污染宿主终端，又能在工具失败时把工具自己的 stderr 带进错误消息与导入进度面板。
   - **上游工具无静默参数**：ncmdump（taurusxin/ncmdump）仅有 `-h/-v/-d/-r/-o/-m`，`[Done]` 输出为无条件 `std::cout`，因此只能在**调用侧**解决。
5. **产物校验与属性抽取**：调用后扫描解密产物（探测扩展名/格式），**抽取音质属性**登记；原 ncm 保留于 `ncm_raw_dir`，不删除。
6. **登记**：写入 `conversion_records`（⚠️ 当前代码尚未实现该写入，见 §2.5 实现状态注；NCM 转换目前仅经 `db::insert_record` 登记到 `download_records`）。
7. **失败处理**：超时/非零退出/无产物 → 标记 `failed`，不删原文件，不阻断主流程。
> 该设计兼容常见 NCM dump 工具（多为 CLI，输出到同级目录）；工具为 GUI 或参数不同，仅调 `command_template` 即可，无需改代码。
> **自动转换规则**：只要 `tool_ready()` 为真（工具已配置），下载/导入/散落发现的 .ncm 一律自动转换；无工具时仅暂存 `download/pendingNcm`，不丢文件，配置工具后自动清积压。
> **转换进度**：逐首进度经 `progress::ProgressTracker` 上报（动作 `convert`），失败原因写入 `last_error`；对外接口 `GET /api/import-progress`。

## 5. 本地曲库扫描与音质抽取

- **触发**：独立 `scan` 子命令，也可在 `sync` 前自动执行。
- **遍历范围**：musiclibrary 下可播放音频；`.ncm` 原文件不解析（加密），其解密产物才抽取。
- **属性来源**：`lofty` 读取技术信息（FLAC: sample_rate/bits_per_sample；MP3: sample_rate/bitrate 等）；`ffprobe` 作回退。
- **匹配 song_id（clean_name_db）**：
  - 主（可靠）：下载/导入时自控制文件名并立即写 `song_id → file_path` 入 SQLite；文件名不含 song_id，关联靠 DB（真相源）。
  - 辅（存量回溯）：对启用前已有文件，按 标题+艺人+专辑 元数据模糊匹配 song_id；低置信度标 `needs_review`，不擅自绑定。
- **写入**：download_records（含音质字段与 `file_mtime`）；本地扫描/导入文件 `song_id=NULL`，不建 `songs` 行（本地文件与网易云 id 空间解耦，播放/详情/封面一律按 `local_id` 检索）。作为去重与升级判定基础。

### 5.1 增量扫描门控（已实现，Phase 1）

核心结论：**扫描的 I/O 大头是逐文件 `lofty` 抽取，而非目录遍历本身**。因此提速点为"跳过未变文件的抽取"，而非"跳过目录遍历"。

- **机制**：`scan_file` 先按 `file_path` 查 `download_records`（含缓存的 `file_size` 与 `file_mtime`）；当磁盘文件的 `(size, mtime)` 与缓存**完全一致**时，直接跳过 `lofty` 抽取（复用既有记录），仅 `scanned` 计数 +1；否则才抽取并 `UPDATE`/`INSERT`。
- **门控键**：`(file_size, file_mtime)`。选二者组合而非单纯 mtime，是为规避"原地重写同大小文件导致 mtime 变化但不重抽"的误判极少出现、且重抽成本可忽略；同时避免"仅 mtime 变但内容未变（如批量 touch）"被误判为变更而重抽——此场景下 mtime 变会触发一次无害的重抽。
- **收益**：曲库规模下，未变文件占绝大多数，扫描从"N 次 lofty"降为"N 次 `stat` + 少量 lofty"，对万级文件仍近瞬时。
- **成本**：`download_records` 增加 `file_mtime INTEGER` 列（迁移：`ALTER TABLE ... ADD COLUMN file_mtime INTEGER`）；旧库自动迁移，无数据丢失。

### 5.2 外部增删检测（档位②：启动自动扫描 + 孤儿清理，已实现）

针对"用户在工具外（如 Explorer）增删/移动文件，曲库索引须同步"的需求：

- **新增**（Explorer 拷入）→ 扫描按 `file_path` 幂等入库（§5.1 门控判定为"路径不存在→抽取入库"）。
- **修改**（重命名/换标签/替换文件）→ `(size, mtime)` 失配触发重新抽取并 `UPDATE` 覆盖。
- **删除/移动**（Explorer 删掉）→ `scan_library` 末尾调用 `prune_missing`：删除 `download_records` 中 `status='downloaded'` 且对应文件在磁盘已不存在的记录（`removed` 计数）。**直接校验磁盘存在性**（`std::fs::metadata`），而非按路径字符串比对，规避 Windows 大小写/分隔符差异误判。
- **触发时机（档位②）**：① app 启动即后台自动跑一次 `scan`（含孤儿清理，失败仅告警不阻断启动）；② 点"扫描"按钮（`POST /api/scan`）手动触发。两者均含门控与清理，刷新列表即与磁盘一致。
- **未做**：档位③（notify 实时监听，秒级反映）留作 Phase 2 可选；若做，仍需保留本档位②启动扫描作兜底（监听线程未启动期间的改动须靠启动扫描补偿）。

### 5.3 NTFS MFT / USN 提速方案评估（决策记录，不采用）

评估过"直接读 NTFS MFT 主文件表跳过逐个文件扫描"的提速设想：

- **直接解析 $MFT**：需管理员提权 + 原始卷访问（文件占用时有锁冲突），且要自处理常驻/非常驻属性、文件名碎片、FRN 回溯等，脆弱且 Windows 强绑定；**MFT 只给文件级元数据，给不了音频标签**——它提供的信息与 `(size, mtime)` 门控**等价**，却换来大量复杂度，故不采用。
- **USN Change Journal（更"正统"）**：`FSCTL_ENUM_USN_DATA`/`FSCTL_READ_USN_JOURNAL` 由文件系统直接给目录树增删改记录，无需遍历；但有四前提——① 需提权开 `\\.\X:` 卷句柄；② 非系统盘/外接 NTFS/ exFAT **无日志**；③ 日志会**回绕截断**，截断后必须回退全量扫描；④ Rust 下为非安全 FFI，实现/测试成本高。代价对 Phase 1 不划算。
- **结论**：Phase 1 采用 §5.1 增量门控 + §5.2 档位②，跨平台、零常驻、可靠；USN 仅在未来"固定盘实时监控自动入库"场景作为可选增强，且须叠加启动扫描兜底。

## 6. 文件存储组织（已定，Phase 1）

- **物理布局由 `config.library.file_scheme` 决定**（默认 `artist_album`）：
  - `artist_album`：`<artist>/<album>/<title>.<ext>`（默认）
  - `album`：`<album>/<title>.<ext>`
  - `artist`：`<artist>/<title>.<ext>`
  - `flat`：`<title> - <artist>.<ext>`（平铺于曲库根）
  - 切换方案见 docs/05 §4c（全量重组 + 警示 + 回滚）。
- **专辑归属虚拟化**：专辑/流派/年份不体现在目录，全部存 DB；按专辑浏览由 DB 查询实现。
- **同名消歧**：同艺人同曲名（罕见）冲突时，文件名追加短标识（专辑缩写或短哈希），不破坏整洁。
- **NCM 解密产物**：转换后音频按上述方案落到曲库正式位置（格式=原始音频格式）；原始 `.ncm` 归档到 `download/ncm/`（有工具）或暂存 `download/pendingNcm/`（无工具）。顶层 `_ncm_raw/` 已废弃，统一到 `download/` 体系（见 docs/05 §11）。
- **Phase 2 增强（非阻塞）**：统一写/校正 ID3 标签、更精细命名、按专辑虚拟视图前端展示。

## 7. 歌曲导入（FR-10）

- 指定**外部源文件夹**（不在 musiclibrary 内），将其音频文件导入并整理进曲库。
- **方式**：`copy`（默认、安全、保留源）/ `move`（写入校验成功后删源；破坏性，须显式确认 + 先写后删，失败即中止保留源）。
- **落盘**：按 `config.library.file_scheme` 组织（默认 `<artist>/<album>/<title>.<ext>`，见 §6）；标签缺失回退文件名解析并标待整理。
- **入库**：立即对该批文件抽取属性并 DB 登记（复用 §5 扫描逻辑）。
- **song_id 关联**：导入文件通常无 song_id，走"存量回溯"模糊匹配，低置信度标 `needs_review`。

## 8. 播放范围与文件服务（FR-11）

- **播放目标**：仅库中**可播放音频**（解密后的常规格式）；`.ncm` 未转换前不可直接播放（列表可展示但标"待转换"）。
- **文件服务**：Rust 在 localhost 起轻量 HTTP 服务（手写 Range/206 流式响应），按 `local_id` 检索 `download_records` 取路径并流式提供音频；既是拖动 seek 所需，也是核心"文件 URL"接口（见 02 §2.9）。封面同理按 `local_id` 取内嵌 APIC，无则 204。
- **UI 承载**：GUI 壳用 HTML5 `<audio>`（播放/暂停/seek 原生）；核心不耦合播放逻辑，保证 UI 壳可替换。
