# docs/05 — 曲库数据目录（.mt）与启动定位设计

> 状态：待审阅冻结。冻结后依 §8 实现。
> 关联：docs/03 §3（config）、docs/03 §8（按 local_id 流式）。
> 背景：上一轮确认数据库/配置文件当前靠相对 CWD 定位（`./app/data`），双击 GUI 的 exe 会落到另一份空库。本方案把数据收归到用户指定的曲库下的 `.mt/` 隐藏目录，从根上消除 CWD 依赖，并把「指定曲库」固化为启动首步。

## 1. 目标

- 「指定曲库」成为应用启动后首要环节，以**首次启动初始化向导**（指定曲库 + 选文件结构方案 + 选 NCM 工具 +（可选）设本地网易云音乐曲库目录）形式采集。
- 初始化完成后进入主界面；主界面通过「设置」按钮可重新配置上述各项及其他设置，「导入歌曲文件夹」只在主界面出现。
- 在用户指定的曲库根下新建隐藏目录 `.mt/`，集中存放该曲库的应用数据（配置 / 数据库 / 日志 / NCM 工具 / 说明文档）。
- 彻底消除相对 CWD 路径歧义；曲库用绝对路径，数据随曲库走（移动硬盘可直接带走）。

## 2. 目标目录结构

```
<曲库根>/
├─ download/                   # 已下载完成的文件（下载模块落点）
│  ├─ ing/                     # 正在下载的文件（临时），完成即从 ing 移入 download
│  ├─ ncm/                     # 已转换 ncm 的原始 .ncm 归档（转换后保留原始）
│  └─ pendingNcm/              # 无 ncm 工具时，待转换的 .ncm 暂存
├─ <artist>/<album>/...        # 音乐文件（按艺人/专辑组织，经应用整理后）
└─ .mt/                        # 本应用隐藏数据目录（指定曲库时新建）
   ├─ config.toml              # 该曲库的**曲库级**配置（[paths] + [library]；app 级设置在 exe 目录）
   ├─ library.db               # 该曲库 SQLite 索引
   ├─ （auth.json 已移除）      #   网易云登录功能 2026-10-29 删除，本目录不再存凭证
   ├─ app.log                  # 运行日志
   ├─ README.txt               # 说明文档（见 §7）
   └─ tools/                   # NCM 解密工具存放处
      └─ ncmdump.exe           # 用户放置，或「指定 NCM 工具」时自动复制到此
```

## 3. 配置结构（双文件：app 级 + 曲库级）

> **2026-11-04 拆分**：`.mt/config.toml` 现在**只**存曲库级设置；应用自身设置与「当前曲库路径」
> 移到 exe 目录的 `kqk-app.toml`。详见 docs/03 §3。

`paths.app_data` 的语义从「`./app/data`」改为「`.mt` 目录本身」。各路径重新锚定：

**曲库级**（`<曲库根>/.mt/config.toml`）：

```toml
[paths]
app_data     = "<曲库根>/.mt"          # 应用数据根 = .mt
download_root = "<曲库根>"             # 曲库根 = .mt 的父目录（扫描根）
download_dir = "<曲库根>/download"    # 已下载完成文件落点
download_ing_dir = "<曲库根>/download/ing"  # 下载中临时文件
ncm_raw_dir  = "<曲库根>/download/ncm"   # 已转换 ncm 原始归档（顶层 _ncm_raw 已废弃，统一到 download 体系）
tools_dir    = "<曲库根>/.mt/tools"    # NCM 转换工具存放处

[library]
file_scheme   = "artist_album"        # 曲库文件结构方案，见 §4a：artist_album | album | artist | flat
name          = "我的曲库"            # 曲库名称（缺省回退到曲库目录名）
```

**app 级**（`<exe 目录>/kqk-app.toml`）：`last_library_dir`（当前曲库路径）+ `[netease]` / `[ncm]` /
`[scanner]` / `[import]` / `[server]` / `[logging]` / `[ui]` 各段（内容见 docs/03 §3.1）。

> `db.rs` 的 `open()` 已是 `app_data.join("library.db")`，`app_data` 改为 `.mt` 后无需改动核心逻辑，仅路径语义变化。

## 4. 启动定位与两种界面态（app 配置中的曲库记忆）

「启动记忆」不再使用独立的 launcher 文件，而是作为 app 级配置的一个字段：

- 位置：应用程序（exe）所在目录下的 `kqk-app.toml`，用 `std::env::current_exe().parent()` 解析（绝对路径，不依赖运行时 CWD）。
- 内容（TOML）：`last_library_dir = "<曲库根绝对路径>"`。

启动流程（cli / gui 共用，`config::load_startup`）：

1. 读 `kqk-app.toml`：
   - 若 `last_library_dir` 指向的目录存在、且其下 `.mt/config.toml` 存在 → 直接加载该曲库（静默），进入 **§4b 主界面态**。
2. 否则 → 进入 **§4a 初始化向导态**（首次运行 / 曲库被移除后）。

> 旧版 `musicmt-launcher.toml` 会在首次启动时自动迁移进 `kqk-app.toml`（见 docs/03 §3.3）。

> 两种界面态的核心区别：初始化向导集中采集「曲库根 + 文件结构方案 + NCM 工具」三项；主界面则展示曲库内容，并通过单独的「设置」按钮可重新配置这些项（连同其他设置），「导入歌曲文件夹」也只在主界面出现。

### 4a. 首次启动初始化向导（3 步）

GUI 首屏（`/api/status` 返回 `library_configured: false` 时）呈现向导，逐步采集：

- **步骤 1 — 指定曲库**：
  - 用户选/输入曲库根目录（含「浏览」按钮，走 §5 的原生目录选择）。
  - 进入下一步前完成 §5 的「初始化曲库」动作（建 `.mt`、config/db/README、建 download 体系、写 launcher）。
  - 若所选目录已存在 `.mt/config.toml`（之前初始化过），则视为「加载已有曲库」，跳过步骤 2/3 默认值、直接进入主界面。
- **步骤 2 — 选择曲库文件结构方案**（`[library] file_scheme`，见 §3）：
  - 提供 4 个选项（单选，默认选中 **`artist_album` 艺人/专辑/曲目**）：
    - `artist_album`：`<artist>/<album>/<name>.<ext>`（默认）
    - `album`：`<album>/<name>.<ext>`
    - `artist`：`<artist>/<name>.<ext>`
    - `flat`：`<name> - <artist>.<ext>`（平铺在曲库根）
  - 写入 `config.library.file_scheme`，立即生效于后续导入整理。
- **步骤 3 — 选择 NCM 工具**：
  - 先自动检测 `<曲库根>/.mt/tools/` 是否已有 `ncmdump.exe`（§6）；有则默认启用并显示路径。
  - 若无：提供「指定 NCM 工具」入口（选本地 `.exe` + 「复制到本曲库 `.mt/tools`」勾选框，默认勾选），逻辑同 §6。
  - 用户也可在此步选择「暂不配置」（留空，后续在 `.mt/tools` 放置或主界面设置里再配；ncm 导入/扫描将走 `download/pendingNcm/` 暂存）。

- **步骤 4 —（可选）设置本地网易云音乐曲库目录**（`[netease] library_dir`，见 01 FR-15）：
  - 提示「如你用网易云官方 APP 维护了一份曲库，可在此指定其目录，便于一键『从本地网易云音乐曲库更新』」。
  - 提供文本框 + 「浏览…」按钮（原生目录选择，见 NFR-02）；可留空（跳过，日后在设置页再配）。
  - 写入 `netease.library_dir`；为空时「从本地网易云音乐曲库更新」按钮点击后引导先选目录（不报错退出）。

完成 4 步 → 进入主界面态。

> CLI 无向导界面：`mt-cli library <dir>` 复用 §5 初始化（步骤 2 取 `file_scheme` 默认 `artist_album`，步骤 3 仅做自动检测）；其余命令无曲库时报错提示。

### 4b. 已配置主界面态

- 展示曲库内容（曲目列表/播放/从本地网易云音乐曲库更新等，沿用现有主界面）。
- **「设置」按钮**（主界面右上或菜单）：打开设置面板，可重新配置：
  - 曲库位置（=重新走 §5 换库；换库前提示）
  - 曲库文件结构方案（`file_scheme`；切换时按 §4c 处理）
  - NCM 工具（指定/复制/清空，§6）
  - 其他设置（音质策略、并发数等既有 config 项；网易云服务端能力已移除，见 01 FR-12）
- **「导入歌曲文件夹」按钮**：仅在主界面出现（见 §5b），调用现有 `import_folder`，目标按 `file_scheme` 组织、ncm 走 `download/` 体系。

### 4c. 切换文件结构方案时的重组（已确认）

- 用户在设置里把 `file_scheme` 改到与当前不同的值时：
  - **先弹警示**：明确告知「曲库文件会按新方案整体移动/重命名，目录结构将大幅变化，建议在媒体播放器/其他工具中退出本曲库后再操作」。用户须二次确认。
  - 确认后执行 **全量重组**：遍历曲库内所有已入库文件（`download_records` + 磁盘），按新 `file_scheme` 计算目标路径，`move` 到新位置，并更新 DB 中 `file_path`；扫描/孤儿清理随后自愈。
  - 重组为阻塞后台任务（带进度），期间禁用相关写操作；失败可回滚（先记录 old→new 映射，失败按映射还原）。
- 仅「新导入/新下载」走新方案的方案（不重组已有）**未采纳**；本应用采用「切换即全量重组 + 警示」。

## 5. 指定曲库流程（`library_directory_handler` 改造）

当前 `library_directory_handler`（`serve.rs`）仅更新 `download_root` 并 save config。改造为完整「初始化曲库」：

1. canonicalize 目标目录，去 `\\?\` 前缀（沿用既有处理）。
2. 创建 `<dir>/.mt/`（Windows 下设为隐藏属性）。
2b. 创建下载目录结构：`<dir>/download/`、`download/ing/`、`download/ncm/`、`download/pendingNcm/`（见文末 §11）。
3. 在 `.mt` 内初始化 `config.toml`：
   - `download_root = <dir>`，`app_data = <dir>/.mt`，`download_dir = <dir>/download`，`download_ing_dir = <dir>/download/ing`，`ncm_raw_dir = <dir>/download/ncm`，`netease.library_dir = ""`，`logging.path = <dir>/.mt/app.log`，`library.file_scheme = "artist_album"`（默认，可由向导步骤 2 覆盖）。
   - 其余沿用默认或从旧配置迁移（首版：沿用默认配置模板，仅锚定路径）。
4. `db::open(new_cfg)` 初始化 `library.db`（`create_dir_all(app_data)` + `init_schema`）。
5. **NCM 检测**：检索 `<dir>/.mt/tools/` 是否存在 `ncmdump.exe`（候选名见 §6）→ 有则写 `ncm.tool_path`（`tool_ready()=true`）；无则 `tool_path` 留空（`tool_ready()=false`）。
6. 写 `README.txt`（模板见 §7）。
7. 更新 `musicmt-launcher.toml` 的 `last_library_dir = <dir>`。
8. **换库**：替换 `AppState` 中的 `cfg`（Arc<Mutex<Config>>）与 `conn`（Arc<Mutex<Connection>>，用新 db 重连）；触发一次后台扫描（`spawn_boot_scan`）。（原 `client.auth_store`/`load_auth()` 网易云登录态相关逻辑已于 2026-10-29 移除，不再存在。）
9. 返回 `{ ok, library_dir }`。

> ⛔ 下载流程（ing → download → 应用处理）**服务端下载已隐藏（2026-10-29）**：原「网易云下载模块」将进行中文件写入 `download/ing/`、完成后移动到 `download/`、由整理/入库逻辑按 `file_scheme` 组织入库（去重/升级）。此流程**代码保留、UI 隐藏**，供未来基于官方开发者 API 复用下载窗口（见 01 FR-04 / 02 §2.4）。本地导入（FR-10/FR-14）不经过此流程产生下载。

> GUI 已持有 `Arc<Mutex<Connection>>`，换库即 `*conn.lock() = db::open(new_cfg)?`，无需重启服务。

### 5b. 导入歌曲文件夹（主界面）

- 前端「导入歌曲文件夹」按钮（仅在 §4b 主界面出现）→ 选源文件夹 + 复制/移动模式 → `POST /api/import`。
- 后端 `import_handler`（`import::import_folder`）：目标目录按 `config.library.file_scheme` 组织（复用 §11 的 `target_path(scheme, meta)`）。
- **NCM 导入已实现**：`import.rs` 的 `import_ncm` 分支——有 ncm 工具时转换后按本地文件入库（song_id=NULL，与扫描/导入一致），原始 `.ncm` 归档 `download/ncm/`；无工具时 `.ncm` 暂存 `download/pendingNcm/`（不入库，导入结果增加 `pending` 计数）。顶层 `_ncm_raw` 已废弃，统一走 `download/` 体系。
- 导入完成触发一次扫描/整理收尾。

## 6. NCM 工具检测与复制

> **核心规则（2026-10-28 与用户确认）**：「只要指定了 NCM 工具就自动走转换歌曲的逻辑」。
> 唯一判据 = `config.ncm.tool_ready()`（即 `tool_path` 指向一个**存在的文件**）；不再有 `enabled` 这类独立开关。

- **检测**（指定曲库 & 启动加载时）：在 `<曲库根>/.mt/tools/` 下查找候选名（`ncmdump.exe` 为主，可扩展 `ncm_dump.exe` 等）。找到则写 `ncm.tool_path`（`tool_ready()=true`）；找不到则 `tool_path` 留空（`tool_ready()=false`）。
- **用户指定**（前端 UI + 后端 `POST /api/ncm-tool`）：
  - 请求体：`{ "path": "<用户选择的工具绝对路径>", "copy_to_library": true }`。
  - `copy_to_library = true`（默认）：复制到 `<曲库根>/.mt/tools/<同名文件>`，`tool_path = <曲库根>/.mt/tools/<同名>`。
  - `copy_to_library = false`：不复制，`tool_path = 用户原路径`。
  - 保存配置后**立即自动调用 `import::process_pending_ncm`**，把 `download/pendingNcm/` 积压的全部 `.ncm` 转换入库（已实测：指定工具后 `pendingNcm` 2 → 0，曲库新增 2 首）。
- 复制实现：`std::fs::copy(src, dst)`；目标目录 `create_dir_all(<dir>/.mt/tools)`。

### 6.1 三种时序的行为统一（用户问询梳理）

| 时序 | 初始 ncm 状态 | 下载/导入得到的 .ncm | 曲库内散落 .ncm（扫描发现） | 何时转换 |
|------|--------------|----------------------|------------------------------|----------|
| ① 初始化未指定 | `tool_ready=false` | 暂存 `download/pendingNcm/`（不入库） | 弹窗询问 → 选「移入 download 并处理」→ 暂存 `pendingNcm`（无工具） | 用户后续指定工具时自动清积压 |
| ② 初始化即指定 | `tool_ready=true` | 转换 → 音频入库、原始 .ncm 归档 `download/ncm/` | 弹窗询问 → 选「移入 download 并处理」→ 立即转换入库 | 即时 |
| ③ 初始化未指定、之后指定 | 先 `false` 后 `true` | ① 期间暂存 `pendingNcm`；② 指定工具瞬间 `process_pending_ncm` 全部转换入库 | 同上，指定工具后再次扫描/整理即转换 | 指定工具的瞬间自动清积压 |

> 结论：无论哪种时序，最终状态都收敛到「有工具→转换入库」；无工具期间只暂存不丢文件。**指定工具是触发转换的唯一动作**，与「何时初始化」无关。

### 6.2 曲库内散落 .ncm 的发现与处理

- **发现**：`library::scan_library` / `scan_dir` 遍历曲库时，凡 `download/` 体系（`ing`/`ncm`/`pendingNcm`/`_ncm_raw`）之外、扩展名为 `.ncm` 的文件，记入 `ScanStats.loose_ncm`（仅记录路径，不入库）。
- **询问（GUI）**：扫描完成后 `status`/scan 响应带回 `loose_ncm` 列表；前端弹出「发现散落的 .ncm 文件」对话框，默认建议「移入 download 并处理（推荐）」，另提供「暂不处理」。
  - 选「移入 download 并处理」→ `POST /api/ncm/organize { paths }` → 逐个 `import_ncm(Move)`：有工具→转换入库、无工具→暂存 `pendingNcm`。处理后清空共享散件列表。
- **处理（CLI）**：`mt-cli scan` 打印散件列表；`mt-cli ncm-organize` 一次性处理散落文件 + `download/pendingNcm` 积压（先清积压、再处理散落，避免重复计数）。

## 7. README.txt 模板

```
musicMT 曲库数据目录
========================

本目录（.mt）由音乐管理工具 musicMT 自动创建并维护，是该曲库的隐藏数据目录。

存放内容：
- config.toml   本曲库的配置文件（曲库根目录、音质策略、本地网易云曲库目录等）
- library.db    本曲库的音频索引数据库（扫描抽取的音质元数据）
- （auth.json 已移除）  网易云登录功能 2026-10-29 删除，本目录不再存凭证
- app.log       运行日志
- tools/        NCM 解密工具（ncmdump.exe）存放处，应用会自动检测并使用

说明：
- 本目录与音乐文件相互独立。删除本目录【不会】删除你的音乐文件。
- 当你不再需要该曲库、或要移除/迁移曲库时，可以【安全删除整个 .mt 文件夹】，
  这只会清除该曲库的索引与配置，音乐文件不受影响。
- 如需使用 NCM 解密功能，请把 ncmdump.exe 放入 tools/ 目录
  （或在应用内「指定 NCM 工具」，应用会自动复制到此目录）。
```

## 8. 实现任务拆分

1. `config.rs`：新增 launcher 读写辅助（`load/save_last_library`）、NCM 检测辅助（`detect_ncm_tool`）；`[library] file_scheme` 字段与 `target_path(scheme, meta)` 组织逻辑；`app_data` 语义注释更新。
2. `serve.rs`：`library_directory_handler` 改造（§5，含 file_scheme 默认写入）、新增 `ncm_tool_handler`（§6）、启动加载改用 launcher + `.mt`、换库逻辑、`/api/status` 增加 `library_configured` 与 `library_dir`；新增 `reorganize_library(new_scheme)`（§4c 全量重组 + 回滚映射）。
3. `cli/main.rs`：cfg_path 改为 launcher 定位的 `.mt/config.toml`；新增 `library <dir>` 子命令；未配置曲库时相关命令给出提示。
4. `gui/lib.rs`：启动改用 launcher 定位；未配置曲库时进入引导态（首屏由前端处理）。
5. `app/gui/frontend/app.js`：
   - **初始化向导**（§4a）：3 步（指定曲库 → 选 file_scheme → 选 NCM），`library_configured=false` 时首屏呈现。
   - **主界面态**（§4b）：「设置」按钮打开设置面板（曲库位置 / file_scheme 切换带警示 / NCM / 其他）、「导入歌曲文件夹」按钮（§5b）。

## 11. 下载目录与流程（⛔ 服务端下载 UI 已隐藏，2026-10-29；代码保留预留）

- 曲库根下新增 `download/`（已下载完成文件落点）与 `download/ing/`（下载中临时文件）。
- 下载模块：进行中写入 `download/ing/<name>.<ext>`；下载完成后 `rename`/`move` 到 `download/<name>.<ext>`。
- 应用后续逻辑：scan_library / sync 收尾按元数据将 `download/` 内文件组织到 `download_root/<artist>/<album>/<name>.<ext>`（复用现有 `target_path` 逻辑）并登记入库（去重 / 音质升级）。`download/` 在 `download_root` 之下，扫描自然纳入。
- NCM 文件分支（下载得到 .ncm）：
  - 有 ncm 工具（`.mt/tools/ncmdump.exe` 或配置 `ncm.tool_path`）：调用工具转换 → 转换后音频按业务整理移入曲库正式位置（`download_root/<artist>/<album>/`）；**原始 .ncm 移到 `download/ncm/` 归档保留**。
  - 无 ncm 工具：把 .ncm 移到 `download/pendingNcm/` 暂存，待用户配置工具后再转换（pendingNcm 由「指定 NCM 工具 / 转换」功能后续处理）。
  - `download/ncm/` 与 `download/pendingNcm/` 为 `download/` 下约定子目录（固定名，不另增配置项）。
- 配置：`[paths]` 新增 `download_dir = <曲库根>/download`、`download_ing_dir = <曲库根>/download/ing`（§3）。
- 实现任务：下载模块落点改造（写 ing → 移 download → 整理入库）并入 Phase 1 下载/同步实现。

- **手动导入 ncm（已实现）**：导入含 ncm 的文件夹走 `download/` 体系（见 §5b）——有工具则转换入库、原始 `.ncm` 归档 `download/ncm/`；无工具则 `.ncm` 暂存 `download/pendingNcm/`。顶层 `_ncm_raw` 已废弃。
- 普通音频文件（非 ncm）「应用根据逻辑处理」已确认：**按元数据重组织到 `download_root/<artist>/<album>/` 并入库去重**（复用 `target_path`）；ncm 分支已明确转换后音频移入曲库正式位置。

### 11.1 实现状态（2026-10-27）

落点改造已在 `app/core/src/library.rs` 落地并通过单元测试（`download_landing_tests::download_landing_ing_download_and_ncm_branches`）：

- `sync_from_netease` 下载流程改为：字节先写 `download/ing/<id>.<ext>` → 完成后 `rename` 到 `download/<id>.<ext>` → 调 `process_downloaded_file` 整理入库；该阶段消耗一次配额。
- 新增 `process_downloaded_file(cfg, conn, dl_path, song) -> ProcessOutcome`：
  - 普通音频（非 ncm）：`rename` 到 `target_path(scheme,...)` 正式位置，`register_downloaded_audio` 入库。
  - ncm 且有工具（`cfg.ncm.tool_ready()`）：调 `convert_ncm`（按 `command_template` 执行，默认 `{tool} "{input}"`）在 `download/` 同目录产出解码音频 → 原始 .ncm 归档 `download/ncm/` → 解码音频整理入曲库并入库 → `Downloaded`。
  - ncm 无工具：.ncm 暂存 `download/pendingNcm/`，不入库 → `Pending`。
- `scan_dir` 跳过 `ing`/`ncm`/`pendingNcm`/`_ncm_raw`（旧废弃名）目录，避免暂存区被当作可播放曲库。
- `sync_from_netease` 收尾新增 `pending` 计数；对 `pendingNcm/` 内已暂存的同 id .ncm 做跳过，避免重复下载浪费配额。
- **修复一个既有 bug**：`db::insert_record` SQL 原把字面量 `'downloaded'` 错放在 `source_kind` 槽位，导致所有同步/导入记录 `status` 实际写成 `source_kind` 值、且 `status` 列错位为空，使 `lookup_path_by_song_id`（`status='downloaded'` 过滤）永远查不到——破坏去重与播放。已改为 `VALUES(?1,?2,'downloaded',...)`，14 参数对 14 占位符，验证通过。

> 注：完整 sync 端到端（网易云登录 / 扫码 / 歌单同步 / 动态配额 / 真机 ncmdump 转换）依赖联网与真机，尚未在沙箱实测；落点核心逻辑已由单元级测试覆盖（用假 WAV 与假 ncmdump 产出验证三分支文件移动与入库）。

## 12. 下载管理界面（⛔ UI 已隐藏，2026-10-29；代码保留预留）

### 12.1 界面规格（用户确认）
- 独立下载管理页面/面板。
- 上方控制区按钮：暂停单个 / 暂停全部 / 开始单个 / 开始全部 / 清除已完成 / 清空下载列表。
- 中下部列表（三列）：左=歌曲名（当前下载列表）；中=状态（下载中 / 完成 / 已入库）；右=最新路径（文件落点路径）。
- 状态机：`queued` → `downloading` → `done`（移入 `download/`）→ `imported`（整理入曲库 `artist/album` 并入库）。

### 12.2 后端设计
- 下载任务队列（内存，可选持久化 `.mt/download_queue.json`）：每项含 id、song_id/name、状态、目标路径、进度。
- 并发：原复用 `DownloadConfig.concurrency`（该 `[download]` 配置段已于 2026-10-29 删除，复用下载窗口时应重新定义）。
- 控制 API：`GET /api/downloads`（列表）、`POST /api/downloads/start`（开始单个或全部）、`POST /api/downloads/pause`（暂停单个或全部）、`POST /api/downloads/clear-completed`、`POST /api/downloads/clear`（清空）。
- 暂停实现：下载循环检查取消标志（线程原子 / 任务标志）；当前为阻塞 HTTP 下载，需分块写入以支持中断。
- 依赖网易云登录与联网，端到端实测需用户真机。

### 12.3 实现任务（并入 Phase 1 下载/同步）
- 下载任务队列 + 状态机 + 控制 API（serve.rs）。
