# musicMT 进展小结（2026-10-27）

> 范围：仅汇总本轮讨论落地与待办；历史设计文档以 docs/00–05 为准，不再复述。

## 一、关键结论

1. **下载落点改造已落地并单测通过**
   - 流程：`download/ing/<id>.<ext>` 字节先写 → `rename` 到 `download/` → `process_downloaded_file` 整理入库，该阶段消耗一次配额。
   - `process_downloaded_file` 三分支：普通音频→`target_path(scheme)` 正式位置并入库；NCM 且有工具→`convert_ncm` 解码 + 原 `.ncm` 归档 `download/ncm/` + 入库；NCM 无工具→暂存 `download/pendingNcm/` 不入库（`Pending`）。
   - `scan_dir` 跳过 `ing/ncm/pendingNcm/_ncm_raw` 暂存目录；`sync_from_netease` 对已暂存同 id `.ncm` 跳过，避免重复下载浪费配额。
   - 单元测试 `download_landing_tests` 用假 WAV + 假 ncmdump 验证三分支文件移动与入库。

2. **修复真实缺陷 `db::insert_record`**
   - 原 SQL 把字面量 `'downloaded'` 错放在 `source_kind` 槽位，导致所有同步/导入记录 `status` 列错位，使 `lookup_path_by_song_id`（`WHERE status='downloaded'`）永远查不到，破坏去重与播放。
   - 已改为 `VALUES(?1,?2,'downloaded',...)`，14 参数对 14 占位符，单测验证通过。

3. **导入 NCM 分支已落地**
   - `import.rs` 增 `import_ncm`：有工具时转换后按本地文件入库（`song_id=NULL`）、原 `.ncm` 归档 `download/ncm/`；无工具时 `.ncm` 暂存 `download/pendingNcm/`（不入库，`ImportOutcome::Pending`）。
   - 复用 `library::convert_ncm`（已改 `pub`）与公共 `import_audio_file`。
   - `ImportResult` 增 `pending` 字段；前端导入完成提示增「待转换 N」。单测 `import_ncm_tests` 两分支通过。

4. **下载管理界面已落地（docs/05 §12）**
   - `downloads.rs`：`DownloadManager` 内存队列 + `DlStatus` 状态机（queued→downloading→done→imported，含全局暂停/单条取消）+ 持久化 `<曲库>/.mt/download_queue.json`（重启复位 Downloading→Queued）。
   - `library.rs` 拆 `sync_from_netease` 为 `build_sync_jobs`（联网解析：歌单/配额预扣/去重/直链）→ `download_and_land`（下载+落点，支持取消）。
   - `netease.rs` 增 `download_song_chunked`（分块流式、每分块查取消、进度回调）。
   - `serve.rs`：`AppState` 增 `downloads`；`sync_handler` 改为「解析入队 + 返回 `{queued:N}`」；常驻 `start_worker_pool`（按 `download.concurrency`）；新增 `GET /api/downloads` + `POST /api/downloads/{start,pause,clear-completed,clear}`（均支持 `{id?}` 单条/全部）；队列空闲且配置自动登出时释放设备槽位。
   - 前端：工具栏「下载管理」面板（控制区 + 三列列表 + 行内暂停/继续，1.5s 轮询）；`runSync` 入队后打开面板。测试覆盖状态机 + 冒烟实测 5 端点 + 未登录报错 + worker 池无 panic。

5. **验证基线**
   - `cargo build`（全 workspace，仅 Windows 增量锁权限告警）、`cargo test -p mt-core`（全绿，含 `downloads::tests`、`download_landing_tests`、`import_ncm_tests`）、serve 冒烟均通过。
   - 测试样本与孤儿记录已清理，dev 库回到 0 曲库。

## 二、已确认的设计决策（与本轮无关、长期有效）

- 技术栈：Rust 核心 + 可替换 UI 壳，PC 阶段 Tauri(Material Web)；Electron 排除。
- 网易云为「可配置」可选模块，非默认启用；`configured`（持久）与 `logged_in`（会话）分离。
- 登录：扫码 + 同步后自动登出，释放设备槽位。
- 去重/升级主键=网易云 `song_id`；本地扫描/导入 `song_id=NULL`，不建 `songs` 行。
- 运行时数据收敛于曲库根下 `.mt/`（配置/DB/凭证/日志/工具）；launcher(`musicmt-launcher.toml`, exe 同目录) 记忆上次曲库。

## 三、未决项（待真机/后续）

1. **完整网易云同步端到端未真机验证**：扫码登录、歌单解析、动态配额字段、真机 ncmdump 转换调用、升级策略确认 UI。
2. **rfd 原生目录选择框在 Tauri worker(MTA) 线程是否弹出**：若失败（COM 未初始化）需改主线程或 Tauri dialog API。
3. **切换曲库目录后的旧曲目处理**：当前仅文件缺失才孤儿清理，若期望「整库切换」需另加清空/重建选项。
4. **封面外链回退**：无内嵌封面时当前回 204，外链回退方案待定。
5. **Phase 2 议题**：ID3 标签写入/精细命名/按专辑虚拟视图、本地文件↔网易云模糊匹配（`needs_review`）、USN 实时监听（档位③）、音质升级 ask 清单确认 UI。
