# K music 发布文件夹（dist）

本文件夹是**一键启动的干净发布目录**，直接从这里双击 `k_music.exe` 即可使用，无需先开命令行 / CLI。

当前版本：**v0.7.1**（版本号取自项目根 `Cargo.toml` 的 `[workspace.package] version`，窗口标题与「设置 → 关于」同步显示）。

> ⚠️ **若双击 `k_music.exe` 后窗口打不开 / 白屏**：多为系统缺少 **Microsoft Edge WebView2 运行时**（GUI 基于 Tauri 2 + 系统 WebView2）。
> 请访问微软官网下载安装 **WebView2 Evergreen 引导器**：<https://go.microsoft.com/fwlink/p/?LinkId=2124703>
> （Win11 通常已自带，无需此步；Win10 干净安装 / 离线 / LTSC 版本可能缺失。安装一次后永久可用，无需随包分发。）

## 目录内容
- `k_music.exe` —— **主入口**：双击即启动（自带后端 HTTP 服务 + 桌面窗口）。
  > 构建产物原名 `mt-gui.exe`，由 `tools\package_gui.bat` 在拷入发布目录时改名；手动从 `target\release\` 拷贝时也请改成此名，避免与旧入口并存。
- `mt-cli.exe` —— 命令行工具（可选）：`scan` / `import` / `import-netease` / `ncm-organize` / `library` / `serve` / `--version`。
- `frontend/` —— 前端静态资源（GUI 后端同源提供，请勿删除或改名）。

## 使用
1. 双击 `k_music.exe`。
2. 首次启动进入「初始化向导」：选择曲库目录、**填写曲库名称**、文件结构方案（默认 `artist_album`），随后可选指定 NCM 工具与「本地网易云音乐曲库目录」。
3. 设置完成后即可看到曲库主界面。

> 后端服务端口由系统自动分配（默认配置 `server.port = 0`），无需手动指定；旧实例未退出时已自动回退到空闲端口，不会卡死。

## 运行时生成的文件
- `kqk-app.toml` —— **app 级配置**（本目录内）：应用自身设置（NCM 工具、本地网易云导入源、显示列偏好、服务器等）**外加当前曲库路径** `last_library_dir`。
- `.guest/` —— 未指定曲库时的临时状态（仅首次运行向导阶段存在）。
- `<曲库目录>/.mt/` —— **曲库级配置与数据**：`config.toml`（曲库名称 / 文件结构方案 / 目录布局）、`library.db`（索引）、`app.log`（GUI 运行诊断日志）、`tools/`（NCM 工具）、`trash/`（删除歌曲的可取回区）、`pending-duplicates.json` + `pending-duplicates/`（重复文件的未决组与挂起文件）、`sync-import.jsonl`（独立的同步 / 导入操作流水）、`playstate.json`（播放队列）。

> **配置分两类**：属于「应用」的放本目录（`kqk-app.toml`），属于「某个曲库」的放该曲库的 `.mt/` 下。
> 当前曲库路径是唯一例外——它必须放在应用目录，因为应用得先知道当前曲库才能找到它的配置。

> **配置不会被覆盖**：上述运行时文件在重新构建 / 替换 exe 时**一律保留**，本目录下的测试配置
> （当前曲库路径、NCM 工具、导入源、界面偏好）不会丢失，无需每次重新指定曲库。
>
> **配置带版本号**：`kqk-app.toml` 与 `.mt/config.toml` 内含 `[meta]` 段，记录生成时的版本号与
> 最低兼容版本号。版本兼容时既有配置**原样保留**，只按需更新 `[meta]`；只有结构/字段不兼容时才会
> 重建（先把原文件备份为 `*.conflict-<版本>.bak`），并在「设置 → 配置文件」中说明冲突原因。

## 从本地网易云音乐曲库更新
- 主界面与设置面板都有 **「从本地网易云音乐曲库更新」** 按钮：把本地网易云曲库里本应用还没有的歌曲
  **复制**进当前曲库（只加不删，不联网、不登录、不碰原曲库文件）。
- **尚未设置网易云曲库目录时**，点击该按钮会直接弹出**目录选择框**；选好目录后自动保存并**立即执行更新**，
  无需再去设置面板手动指定。

## 歌词
- 播放时点击播放器上的 **「词」** 按钮打开歌词面板：按播放进度高亮当前行、自动滚动，**点击某行可跳转**到对应时间点。
- 歌词来源优先级：**同名 `.lrc` 文件**（与歌曲同目录同 stem）→ 音频文件**内嵌歌词**。
  - 内嵌支持：FLAC / OGG 的 Vorbis Comment（`LYRICS` / `UNSYNCEDLYRICS`）、MP3 等的 ID3v2 `USLT` 帧。
- 导入歌曲时会**同步导入同目录同名的 `.lrc` 歌词文件**（自定义曲库导入与「从本地网易云音乐曲库更新」均适用）。
- 歌词文本编码自动识别：UTF-8 / UTF-16 / **GBK-GB18030**（中文 lrc 常见）。

## 想自己重新打包？
项目根目录执行 `tools\package_gui.bat`（Windows 双击即可）：编译 release，把 `target\release\mt-gui.exe` 拷成 `k_music.exe`、`mt-cli.exe` 原样拷入，并清理旧版残留的 `dist\mt-gui.exe`（避免两个入口并存）。**前端静态资源（`frontend/`）已由 `app/gui/build.rs` 在 `cargo build` 编译期自动同步到本文件夹**，无需手动拷贝。

> 打包脚本**不会删除或覆盖**本目录下的运行时配置（`kqk-app.toml` / `.guest\` / `library.db` / `app.log`），你在 `dist\` 里的测试配置会一直保留。
> 脚本本身必须保持 **CRLF 行尾 + 纯 ASCII**（文件头部有「编写规范」说明）：否则 cmd.exe 解析会错乱，把行拆成非法命令。

## 命令行快速自检（可选）
```
mt-cli.exe library <曲库目录> artist_album   # 初始化曲库
mt-cli.exe scan                                # 扫描建库（自动发现曲库内散落的 .ncm 并提示）
mt-cli.exe import <文件夹> [copy|move]         # 从外部文件夹导入到曲库
mt-cli.exe import-netease                     # 从「本地网易云音乐曲库目录」增量合并（只加不删）
mt-cli.exe ncm-organize                        # 将散落 .ncm 移入 download 体系、并把 pendingNcm 积压转换入库
mt-cli.exe --version                           # 显示版本号 / 作者 / 项目主页
```

## NCM 工具（解密 .ncm）
- **唯一开关**：`设置/向导` 里「指定 NCM 工具」选到一个有效 exe 即生效。
- **规则**：只要指定了工具，就自动走转换歌曲逻辑——下载、导入、散落 ncm、历史 `pendingNcm` 积压遇到 `.ncm` 一律尝试转换。
- **未指定工具时**：遇到的 `.ncm` 暂存 `<曲库>/.mt/../download/pendingNcm/`，不入库、不丢文件；事后指定工具即自动清积压入库。
- **曲库内散落的 .ncm**：扫描后会弹「移入 download 并处理」对话框（GUI），或 `mt-cli ncm-organize`（CLI）统一处理。
- **转换过程不弹终端窗口**：调用工具时使用 Windows 的 `CREATE_NO_WINDOW` 标志，进程照常运行但**不创建控制台窗口**，因此转换再多歌曲也不会反复闪窗、不会抢焦点。工具失败时会把工具自身的报错信息显示在进度面板里。

## 导入进度（逐首明细）
- 导入 / 从本地网易云曲库更新时，右下角弹出**进度面板**：进度条（已处理/总数）、当前正在处理的文件与动作、**逐条动作日志**、以及入库/跳过/待转换/失败四项统计。
- 动作分五类：**复制** / **移动** / **转换**（.ncm 解密）/ **暂存**（无 NCM 工具时先存起来）/ **跳过**（曲库中已存在）。
- 例：`[复制] 夜色.mp3 → 已入库`、`[转换] 加密歌.ncm → 已入库`、`[暂存] 加密歌.ncm → 待转换`。
- 计数口径：进度条与统计按**源文件**计；动作日志按**真实动作**计（1 个 .ncm 源文件会有「转换」+「入库」两条日志，但只结算 1 首）。

## 重复歌曲：挂起与对比（v0.6.1 新增）

- 重复判定口径 = **歌手 + 歌曲名 + 格式**（格式按小写扩展名，同一首歌的 `.flac` 与 `.mp3` **不算**重复）。
- **手工导入 / 扫描曲库**发现同三元组且库内已有记录时，不直接覆盖：新文件先挂到 `<曲库>/.mt/pending-duplicates/`，顶栏出现「待处理重复 N」角标；**启动时的自动扫描只静默登记，不弹窗**，点角标或点「扫描曲库」才打开对比窗。
- 对比窗一次列出**全部未决组**，每组并排显示两份文件的大小 / 采样率 / 位深 / 格式 / 来源，各带「试听」；可逐组选「保留库内」或「采用新的」，最后「应用所选」批量提交；「稍后处理」/ 关窗保持挂起，下次接着处理。
  - 保留库内：手工导入的源文件**原位不动**，扫描发现的挂起项移入 `.mt/trash/`（可手动取回）。
  - 采用新的：库内记录**原地替换**，`local_id` 不变，播放列表引用与播放队列都不丢；同名 `.lrc` 跟随被采用的那一份。
- 从**本地网易云曲库更新 / NCM 回补**（周期性同步）时，目标已存在且大小相同仍静默跳过，不弹窗打断；大小不同才挂起。同一批里出现两个及以上同三元组的新文件，整组挂起。
- 同一来源、同一大小的文件再次导入仍会挂起、仍会弹窗，但会把**上次的选择作为默认预选项**并显示提示；库内文件或源文件大小变化后该预选自动失效。设置 →「导入」里可「清除同步/导入历史」。
- 所有同步 / 导入事件（含跳过、挂起、决策、失败）写入 `<曲库>/.mt/sync-import.jsonl`，**与 `app.log`（运行诊断日志）分开**；换曲库时未决组留在原曲库的 `.mt/` 下，不会自动清理。

## 播放整组、侧栏与音量（v0.7.1 新增）

- **双击左侧二级列表项**（专辑 / 歌手 / 播放列表）= 立即播放该列表的**整组全量**曲目，从第一首开始；
  双击**单首歌曲**仍按「设置 → 播放 → 自动播放列表数量」生成队列并从点击的那首开始播。
- **一级菜单 / 二级分组栏宽度**：拖动栏右缘的窄把手即可调整，两级各自独立记忆；栏顶的收起按钮 « 可把该列收成**只留小图标的窄条**，
  边界仍保留一条**常驻窄把手**用于展开。收起 / 展开状态与宽度重启后自动恢复。
- **音量**：播放条进度条右侧新增音量滑块与静音按钮，拖动即时改变实际音量，点按钮静音 / 恢复原音量；重启后保留、换曲库不变。
- 上述宽度、收缩状态、音量与静音都保存在 `dist\kqk-app.toml` 的 `[ui]` 段（`sidebar_width` / `group_width` /
  `sidebar_collapsed` / `group_collapsed` / `volume` / `muted`），只就地更新，不会抹掉你写的注释或其它设置。
- 专辑 / 歌手 / 全部曲库统一称为**智能播放列表**，播放队列标题与空态都带「智能播放列表 ·」前缀；
  它们仍是自动生成的浏览视图，不写入播放列表数据库，也不支持移除成员 / 重命名 / 重排。
